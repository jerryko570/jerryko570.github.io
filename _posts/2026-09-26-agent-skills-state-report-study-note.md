Vercel 블로그에서 "State of Agent Skills"라는 리포트가 올라왔다. skills.sh 레지스트리가 7개월 만에 스킬 100만 개를 넘겼다는 내용인데, 숫자보다 "스킬이 대체 뭔지, 그게 왜 이렇게 빠르게 늘었는지"가 더 궁금해서 읽어봤다.

생태계 현황 리포트라 딱딱할 것 같았는데, 의외로 흥미로운 관찰 몇 가지가 눈에 들어왔다.

## 1️⃣ 이게 뭐냐?

스킬은 AI 에이전트에게 특정 업무 방식을 가르치는 파일이다. 에이전트 자체는 다양한 일을 처리할 수 있지만, 우리 팀이 코드 리뷰를 어떤 식으로 하는지, 고객 메일을 어떤 톤으로 쓰는지 같은 구체적인 맥락은 모른다. 스킬이 그 빈틈을 채운다.

Anthropic이 2025년 10월에 Agent Skills를 발표하고, Vercel이 세 달 뒤 skills.sh 레지스트리를 열었다. 리포트가 GitHub이나 App Store, npm과 성장 속도를 비교했는데, 스킬 생태계가 가장 빠른 것 같았다. 기술적인 코드 없이도 "이 일을 어떻게 하는지"를 텍스트로 설명하면 스킬이 되니까, 진입 장벽이 낮았던 것 같다.

카테고리별로 보면 소프트웨어 공학이 가장 큰 편이고, 고객 커뮤니케이션이나 데이터 처리 같은 범용 업무 스킬이 설치량 대부분을 차지한다. 도메인 특화 스킬보다 크로스인더스트리 쪽이 먼저 채워진 구조인 것 같다.

## 2️⃣ 내가 든 생각

리포트에서 가장 인상적이었던 건 "스킬을 만들 수 있는 사람의 풀이 코드를 짤 수 있는 사람보다 훨씬 크다"는 관찰이었다. 어떤 일을 잘 아는 사람이라면 그 절차와 판단 기준을 설명할 수 있고, 그것만으로도 스킬이 된다는 거다. 코딩이 필수가 아닌 영역이 생긴 것 같았다.

디자이너 입장에서 보면 흥미로웠다. UX 라이팅 가이드라인, 디자인 리뷰 체크리스트, 사용자 인터뷰 정리 방식 같은 것들을 스킬로 만들 수 있다면, 이건 개발자보다 오히려 디자이너 언어에 가까운 영역이기도 하다. 기준과 맥락을 문서로 정리하는 일은 디자이너가 이미 하고 있는 일이니까.

👉🏻 다만 상위 소수의 스킬이 전체 설치량 대부분을 차지한다는 부분도 눈에 띄었다. 많이 만들어졌다고 많이 쓰이는 게 아닌 거다. 잘 만들어진 범용 스킬에 수요가 집중되고, 도메인 특화 스킬은 좁게 쓰이는 구조에 가까운 것 같다.

> 💡 **여기서 드는 질문?**
> 공개 스킬과 회사 내부 스킬의 경계는 어떻게 가져가는 게 맞을까. 리포트는 "차별화는 내부 노하우에서 온다"고 말하는 것 같은데, 어디까지를 스킬로 만드는 게 의미 있는 건지는 아직 잘 모르겠다. 내부 노하우를 너무 잘게 스킬로 쪼개면 관리 비용이 늘어날 것 같기도 하고.

## ⭐️ 마지막으로, 프론트엔드를 공부하는 디자이너 관점에서 느낀 점

공부 끝에 남은 건 "스킬은 코드가 아니라 판단을 파일로 만든 것"이라는 한 줄이다. 어떤 일을 잘 아는 사람이 그 판단을 텍스트로 정리하면, 에이전트가 그걸 참고해서 일한다. 그런 관점에서 보면 디자이너도 충분히 스킬 작성자가 될 수 있는 입장에 가깝다는 생각이 들었다. 코드를 배우는 것과 별개로, 이쪽은 내가 이미 알고 있는 걸 형식으로 만드는 일에 가까우니까.
