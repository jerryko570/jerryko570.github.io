GitHub 블로그에 GitHub Universe 2026 발표 글이 올라왔다. 제목이 "Evolving every layer of the stack"이라서 처음엔 그냥 연례 키노트 요약 글이겠지 싶었는데, 읽어보니 방향이 꽤 달라져 있었다.

Copilot을 단순 코드 보조 도구 이상으로 만들겠다는 건 알고 있었는데, 이번엔 **여러 에이전트를 조율하는 인터페이스** 쪽으로 본격적으로 옮겨가는 것 같다는 인상을 받았다. 그 부분을 중심으로 정리해봤다.

## 1️⃣ 이게 뭐냐?

이번에 공개된 것 중 가장 눈에 들어온 건 **Copilot Fusion**이었다. 추론, 코드 생성, 디버깅, 도구 사용 같은 요구를 분석해서 그에 맞는 모델을 자동으로 조합해 실행한다는 개념에 가깝다. 사용자가 어떤 모델을 골라야 할지 고민하지 않아도 Copilot이 알아서 판단하는 구조다. 내가 이해한 바로는, 이게 사용자 경험 측면에서 꽤 큰 차이를 만들 것 같다.

**Copilot projects**는 여러 리포지토리에 걸친 작업을 병렬 에이전트 세션으로 실행하고, 진행 상황과 에이전트의 결정을 한 곳에서 볼 수 있도록 해준다. 기존엔 리포지토리 단위로 작업하는 느낌이었다면, 이제는 프로젝트 전체를 감싸는 레이어가 하나 생긴 셈에 가깝다.

**Copilot automations**는 이슈 트리아지나 코드 리뷰 같은 반복 작업을 클라우드 워크플로로 자동화하는 기능이다. 실행 결과를 바탕으로 개선안을 스스로 제안하고, 사람이 검토 후 승인하는 방식으로 돌아간다. 발표에 따르면 이 학습 과정이 자동화 품질을 점점 높이는 구조라고 한다.

## 2️⃣ 내가 든 생각

발표 글에서 인상적이었던 부분은 "기획 → 코딩 → 테스트 → 배포의 선형 흐름"이 아니라 "어느 단계에서든 작업이 시작될 수 있는 비선형 흐름"으로 바뀐다는 설명이었다. 에이전트가 구현과 검증을 담당하고, 사람은 방향 설정과 의사결정을 맡는다는 구조다.

디자이너 입장에서 보면 이게 좀 낯선 변화였다. 협업 도구에서 역할이 나뉘는 방식은 보통 "누가 어느 단계를 담당하는가"였는데, 여기서는 에이전트들이 여러 단계를 병렬로 처리하면서 사람이 중간 중간 판단 지점에 서는 모양새가 된다. 책임이 어떻게 나뉘는 건지가 아직 잘 그려지지 않았다.

👉🏻 Copilot code review에 Max 티어가 추가된 것도 같은 흐름의 연장처럼 읽혔다. 속도가 중요한 작업엔 Lite, 더 깊은 리뷰가 필요하면 Max를 쓰는 식으로 목적에 따라 선택하는 구조다. 코드 리뷰 자체가 단계가 나뉘는 작업이 된 것 같다.

> 💡 **여기서 드는 질문?**
> 에이전트가 여러 개 병렬로 돌 때, 사람이 각 결정 지점에서 얼마나 개입해야 하는 걸까. "검토 후 승인"이 반복되면, 이게 자동화인지 결국 사람이 하는 일인지 경계가 흐릿해지는 것 같다.

## ⭐️ 마지막으로, 디자이너-개발자 경계에서 공부하며 든 생각

정리해보니 이번 발표는 "Copilot에 기능이 추가됐다"기보다 "GitHub 자체가 에이전트 오케스트레이션 레이어가 되려는 구조 변화"에 더 가까운 것 같다. 코드를 도와주는 보조 도구였던 자리에서, 여러 에이전트를 연결하고 작업 흐름을 조율하는 플랫폼 레이어로 이동하는 흐름이다. 공부 끝에 남은 건 그 안에서 사람의 판단이 어디에 필요한가라는 질문 하나였다.
