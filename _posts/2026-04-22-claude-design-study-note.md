요즘 Anthropic 블로그를 종종 들어가 보는 편인데, 며칠 전에 `Claude Design` 이라는 새 제품이 올라와 있었다.

읽어보니 "디자이너가 아닌 사람들도 대화로 프로토타입이나 슬라이드를 만들 수 있게 해주는 도구"라고 했다. 디자이너로 일하는 입장에서 좀 묘한 기분이 들어서, 정리해두면 좋을 것 같아 메모를 남긴다.

## **1️⃣ 이게 뭐냐?**

Claude Opus 4.7이라는 새 모델 위에서 돌아가는 비주얼 제작 툴이라고 한다. 주요 타깃은 **디자이너가 아닌 사람들**이었다. 창업자, PM, 마케터처럼 "아이디어는 있는데 시각화 도구를 잘 다루지 못하는 사람들" 말이다.

사용 방식은 단순해 보였다. 예를 들면 이런 식이다.

> "차분한 느낌의 명상 앱 프로토타입 만들어줘. 자연 느낌 색상에 깔끔한 레이아웃으로."

이렇게 말하면 초안이 나오고, 거기서 "다크 모드 토글 추가해줘" 같은 요청을 덧붙여 가며 다듬어 가는 흐름이다. 결과물은 PDF나 PPTX, HTML로 내보내거나 Canva로 보낼 수도 있다고 한다.

👉🏻 그중에서 눈에 띈 건 **"팀의 디자인 시스템을 읽어 와서 적용한다"** 는 부분이었다. 회사 코드베이스랑 디자인 파일을 분석해서 컴포넌트 스타일을 맞춰준다는 설명이 있었다. 이게 진짜로 잘 된다면 꽤 큰 의미가 있겠다 싶었다.

## **2️⃣ 읽으면서 든 생각**

읽다 보니 마음이 조금 복잡해졌다.

Anthropic은 "Canva를 대체하는 게 아니라 보완한다"는 식으로 포지셔닝했고, 실제로 Canva와 파트너십도 맺었다고 했다. 만든 결과물을 Canva로 보내서 편집할 수 있는 흐름도 지원한다고 한다. 다만 이 구도가 오래 갈지는 잘 모르겠다.

읽으면서 이런 질문이 떠올랐다.

> 💡 **디자이너가 아닌 사람이 "초안"을 만든다는 게, 결국 무엇을 바꾸는 걸까?**

지금까지는 디자이너와 비디자이너 사이에 **"눈에 보이는 걸 만드는 능력"** 이라는 벽이 분명히 있었던 것 같다. 머릿속에 있는 걸 누군가에게 보여주려면 피그마든 키노트든 어쨌거나 도구를 배워야 했으니까.

그 벽이 낮아지는 건 맞아 보인다. 다만 초안을 만들어내는 것과 **좋은 디자인을 알아보는 것**은 좀 다른 얘기인 것 같다. PM이 Claude Design으로 화면을 10개 뽑았을 때, 그중에 뭐가 쓸만한지를 골라내는 건 여전히 안목이 필요한 일이다.

## **3️⃣ 디자이너로서 뭐가 달라질까?**

직접 써보지는 못했으니 써봐야 알겠지만, 지금 막연히 드는 생각은 이렇다.

프로덕트 디자이너의 역할이 조금씩 **"화면을 직접 그리는 사람"** 에서 **"비디자이너가 만든 초안을 다듬는 사람"** 쪽으로 옮겨가지 않을까 싶었다. 개발자도 비슷하지 않나. AI가 코드를 잘 써주게 되면서, 짜는 일보다 리뷰하고 구조를 잡는 비중이 점점 커지는 것 같다.

Anthropic이 강조한 "디자인 시스템 자동 적용" 기능도 같은 맥락에서 흥미로웠다. 시스템이 잘 정리돼 있으면 AI가 꽤 쓸만한 걸 만들어 줄 수 있겠지만, 시스템이 없으면 AI도 그냥 흔한 결과물밖에 못 낼 것 같다.

그러니까 결국 **디자이너가 만들어 둔 시스템의 품질이, AI가 만들어 내는 결과물의 천장**이 되는 셈이다.

## **⭐️ 마지막으로, 디자이너-개발자 학습자 관점에서 느낀 점**

이번에 Claude Design 발표를 보면서 가장 크게 다가온 건 **"AI가 디자인을 대신한다"** 가 아니라 **"내가 만들어 둔 시스템이 AI의 결과를 결정한다"** 는 감각이었다.

요즘 코드를 배우면서도 비슷한 걸 자주 느낀다. AI가 좋은 코드를 써주려면 내가 짜둔 구조부터 깔끔해야 한다. 디자인도 비슷한 것 같다. 컴포넌트랑 토큰이 잘 정리돼 있어야 AI가 그 위에서 쓸만한 결과를 낸다.

그래서 지금 시점에 디자이너가 해야 할 건, AI를 따라잡으려 하기보다 **내 시스템을 더 잘 만드는 연습**이 아닐까 싶다. 적어도 지금은 그런 결론에 가까워지고 있다.
