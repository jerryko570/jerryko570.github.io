Vercel 체인지로그를 보다가 작은 업데이트 하나가 눈에 걸렸다. CLI로 정적 파일을 배포하면 1초도 안 걸린다는 내용이었다. 어떻게 가능한 건지 궁금해서 문서를 좀 더 읽어봤다.

기존에는 `vercel deploy`를 치면 빌드 단계를 거쳤다. 컨테이너가 뜨고, 빌드가 실행되고, 결과를 올리고 나서야 URL이 나왔다. 이번 변화는 그 빌드 단계를 통째로 건너뛴다는 거다. 생각해보면 HTML 파일 하나 올리는 데 빌드가 필요한 건 아니니까.

## 1️⃣ 이게 뭐냐?

`vercel deploy`로 정적 파일을 올리면 Vercel이 자동으로 빌드가 필요한 배포인지를 판단한다. HTML, Markdown 파일이 10개 이하고 전체 용량이 5MB 이하면 빌드를 건너뛰고 바로 URL을 내어준다.

지원하는 확장자는 `.html`, `.htm`, `.md`. 조건에 맞는 작은 파일 묶음을 올릴 때만 이 경로가 활성화된다. Vercel CLI 59.16.0 이상이 필요하고, 따로 플래그를 붙이지 않아도 Vercel이 자동으로 조건에 맞는 배포인지 감지한다. `vercel deploy --help`로 옵션을 확인할 수 있다.

발표에서 보여준 예시에는 802ms 배포 시간이 찍혀 있었다. 빌드 컨테이너를 띄우는 시간 자체가 없어지니 이 정도 숫자가 나오는 건 이해가 됐다.

내가 이해한 흐름은 이렇다. 기존: 배포 요청 → 빌드 컨테이너 시작 → 빌드 실행 → 결과 업로드 → URL 발급. 이번: 배포 요청 → 파일 업로드 → URL 발급. 빌드 컨테이너를 기다리는 시간이 없어진다.

## 2️⃣ 내가 든 생각

처음엔 "쓸 일이 있을까?"라는 생각이 먼저 들었다. 그러다 발표 문서를 다시 읽으니 "에이전트가 만든 HTML 리포트를 즉시 공유"하는 시나리오를 명시적으로 예시로 들고 있었다. 코딩 에이전트가 생성한 결과물을 URL로 내보내는 흐름을 이 기능이 뒷받침한다는 거였다.

👉🏻 흥미로웠던 건 배포의 대상 자체가 달라진다는 점이었다. 기존 배포는 "앱을 올린다"는 맥락이었다면, 이건 "파일을 URL로 바꾼다"에 가까운 것 같다. 두 개는 비슷해 보이지만 누가, 왜 올리느냐가 꽤 달라진다. 사람이 아니라 에이전트가 배포 주체가 될 수도 있다는 전제가 깔린 기능처럼 읽혔다.

> 💡 **여기서 드는 질문:** 빌드를 건너뛴다는 건 어디까지 확인하고 올리는 걸까? 접근 제한이나 인증 설정은 어떻게 처리되는 건지 궁금해졌다. 파일을 올리는 주체가 에이전트라면 그 부분이 더 중요해지지 않을까.

디자이너 입장에서는 HTML 프로토타입이나 인터랙션 데모를 빠르게 링크로 공유하는 흐름이 자연스럽게 느껴졌다. Figma 링크처럼 URL 하나만 건네면 된다는 게 협업 맥락에서는 꽤 다른 경험일 것 같다.

## ⭐️ 마지막으로, 배포 흐름을 공부하며 느낀 점

공부 끝에 남은 건, "빌드를 안 한다"는 말이 단순히 속도 향상이 아니라 배포 대상의 정의가 달라진다는 한 줄짜리 인상이다. 빌드가 필요 없는 결과물을 올리는 행위는 앱 배포와는 다른 카테고리인 것 같다는 생각이 들었다. 그게 에이전트가 만든 파일이라면 더더욱.
