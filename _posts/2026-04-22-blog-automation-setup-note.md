이 레포에 며칠마다 자동으로 새 글이 올라가는 시스템을 하루 동안 만들어봤다. 시작할 땐 "몇 줄만 쓰면 되겠지" 했는데, 초반엔 구조 잡는 데, 중반엔 워크플로우가 계속 멈춰서 뭐가 문제인지 찾는 데 시간이 들었다.

끝내고 보니 커밋이 열두 개였다. 오늘의 기록을 단계별로 정리해둔다.

## **1️⃣ 뭘 만들었나**

이번에 만든 건 크게 세 조각이다.

**① 후보 수집 (Python 스크립트)**
`scripts/prepare.py`가 공식 블로그 RSS를 크롤링해서 `candidates.json`에 쌓아둔다. Figma, React, Vercel, Anthropic 공식 블로그만 돌도록 제한했다. Medium이나 dev.to 같은 2차 소스는 뺐다. 글이 너무 다양한 톤으로 섞이면 학습 노트의 일관성이 흐트러질 것 같아서.

**② 글 작성 (GitHub Actions에서 Claude Code 호출)**
`.github/workflows/auto-blog.yml`이 3일마다 돌면서 `anthropics/claude-code-action`을 띄운다. 거기서 `prompts/claude_instructions.md`의 스텝을 따라 후보 중 하나를 골라 한국어 학습 노트로 재구성한다.

**③ 썸네일 자동 생성**
`scripts/thumbnail.py`가 카테고리별 그라데이션 배경에 영어 키워드 한 개만 크게 얹은 썸네일을 만든다. 피그마 시안을 Pillow로 옮긴 거라 폰트 사이즈·정렬만 값으로 관리한다.

## **2️⃣ 연쇄 버그 구간**

문제는 워크플로우를 처음 돌린 순간부터 시작됐다.

**(1) `prompt_file` 키가 없다**
처음엔 Claude Code Action에 `prompt_file:`로 지시문 경로를 넘겼는데, v1 API에선 `prompt:`에 내용을 직접 넣어야 하는 구조였다. 워크플로우에서 `cat prompts/...` 해서 `GITHUB_OUTPUT`으로 밀어넣는 방식으로 바꿨다.

**(2) `max-turns 25`로는 한 편도 못 쓴다**
후보 읽고 → WebFetch로 원문 읽고 → 스타일 가이드 읽고 → 본문 쓰고 → 썸네일 호출하고 → state 업데이트하고… 25턴은 중간에 끊겼다. 60으로 늘렸더니 여유가 생겼다.

**(3) `allowedTools`가 빠져서 파일 쓰기 실패**
Action 기본값으론 Read만 허용되더라. `Read,Write,Edit,Bash,WebFetch,Glob,Grep`을 명시적으로 넣었다.

**(4) `git push` 인증 실패**
`GITHUB_TOKEN`이 있는데도 푸시가 401로 떨어졌다. `git remote set-url origin "https://x-access-token:${GH_TOKEN}@..."`로 원격 URL을 재설정해서 풀었는데, 기본 체크아웃에서 왜 안 되는 건지는 아직 확실히 모르겠다.

**(5) 카테고리 하이픈 문제**
첫 자동 글이 올라갔는데 Chirpy 테마가 `[dev-tools]` 같은 하이픈 있는 카테고리를 링크로 못 깔더라. 카테고리 ID(`dev-tools`)와 프론트매터 표기(`DevTools`)를 분리했다.

각각 따로 보면 사소한 문제였는데, 워크플로우 안에서 연달아 터지니까 디버깅이 제법 고됐다. 에러 하나 고치고 다시 돌려서 다음 에러를 보는 식이라, 한 번 반영에 워크플로우 한 사이클이 그대로 기다림이 됐다.

> 💡 **여기서 든 질문?** 
여기까지 와도 아직 "글의 퀄리티"는 손 못 댄 상태였다. 돌아는 가는데, 나오는 글이 어떤지는 보고 난 뒤였다.

## **3️⃣ 돌려보니 글에서 AI 티가 난다**

첫 자동 생성 글을 열어보니 내가 평소 쓰는 말투가 아니었다. "이는 혁명적 변화다", "많은 개발자들이", "X의 본질은 Y다" 같은 문장이 섞여 있었다. 스크립트가 동작한 것보다 글이 어색한 게 더 큰 문제로 느껴졌다.

그래서 하루의 후반은 구조보다 **톤**을 잡는 데 썼다.

- `prompts/style_guide.md`에 AI 티 나는 표현 블랙리스트를 따로 뒀다. "혁명적", "게임 체인저", "Forrester가 분석한…" 같은 표현이 나오면 바로 빼도록.
- `prompts/author_context.md`로 작성자 페르소나를 분리했다. "단정 대신 조심스러운 관찰", "배우는 중", "질문이 결론보다 앞선다" 같은 축으로.
- `claude_instructions.md`에 **Step 4: 스타일 파일 학습 (필수)**를 못 박았다. 이걸 안 읽으면 이전 패턴이 계속 나왔다.

이렇게 분리하니 한 번의 글이 한 파일에서 전부 해결되지 않고, 스타일·페르소나·지시문 세 층으로 나뉘었다. 처음엔 오버엔지니어링 같았는데, 돌려보니 말투가 흔들릴 여지가 확실히 줄었다.

## **4️⃣ 썸네일도 결국 톤이다**

마지막엔 썸네일을 만졌다. 피그마 시안대로 Pretendard ExtraBold · 그림자 없음 · 배경 밝기에 따라 텍스트 색이 자동으로 바뀌는 v3까지 정리했다. 그러고도 한 가지가 걸렸다. **글자가 너무 컸다.** 260px로 꽉 찬 "Claude"가 답답해 보였다.

폰트 크기 테이블을 전체적으로 180/140/110/90으로 낮췄더니 여백이 숨쉬는 느낌이 들었다. 디자인 쪽에서 늘 하던 조정이라 결국 손이 먼저 갔다.

## **⭐️ 마지막으로, 자동화를 세팅하며 든 생각**

이번에 공부하면서 블로그 자동화에서 중요한 건
**"매일 글이 올라가게 만드는 것"**이 아니라
**"내가 쓸 법한 글만 올라가게 만드는 것"**이라는 생각이 들었다.

기술 쪽 문제는 결국 시간 들이면 풀렸다. 근데 톤은 풀리는 문제가 아니라 **정의하는** 문제였다. 스타일 가이드·페르소나·지시문을 나눠 쓴 것도, 결국 "내 말투를 언어로 한 번 더 설명해두는 작업"에 가까웠다.

잘 돌아가는 파이프라인보다, 파이프라인 끝에서 **내가 낯설어하지 않는 글**이 나오게 만드는 쪽이 훨씬 품이 많이 들었다. 다음 자동 생성 글이 어떻게 올라올지 조심스럽게 지켜볼 생각이다.
