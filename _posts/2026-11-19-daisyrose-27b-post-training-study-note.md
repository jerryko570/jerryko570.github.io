Hugging Face 블로그에서 DaisyRose-27B 발표를 봤다. RadixArk가 처음 공개한 모델인데, 기반이 Qwen3.8-27B이고 거기에 강화학습 기반 포스트 트레이닝을 얹었다는 게 핵심이다. 모델 이름이 낯설어서 클릭했는데, 읽다 보니 꽤 흥미로운 내용이 여럿 있었다.

포스트 트레이닝이라는 단어가 처음엔 낯설었다. 이미 학습이 끝난 모델에 또 학습을 한다는 건데, 에이전트 작업에 특화해서 강화학습을 추가로 얹는다는 게 어떤 의미인지 궁금해서 좀 더 읽어봤다.

## 1️⃣ 이게 뭐냐?

기반 모델 Qwen3.8-27B 위에 Miles라는 자체 프레임워크로 강화학습을 한 번 더 했다. 에이전트 작업이라는 건 단순히 질문에 답하는 게 아니라, 여러 도구를 쓰면서 복잡한 작업을 단계별로 처리하는 모드를 말하는 것 같다. 컨텍스트 윈도우는 256K 토큰이고, Apache 2.0 라이선스로 공개됐다.

학습 데이터를 고르는 방식이 흥미로웠다. 약 1,200개의 과제를 직접 큐레이션했는데, 그냥 어려운 문제들이 아니었다. 기반 모델이 실제로 실수하는 지점을 겨냥해서 설계했다고 한다. 우회 해법이 없어야 하고, 여러 단계가 맞물려야 풀리고, 한 시도당 최대 1.5시간·100회 이상의 도구 호출이 허용되는 과제들이었다.

응답 구조도 나뉜다. 최종 답이 담기는 `content`와 별개로, 모델이 추론하는 과정이 `reasoning_content`에 따로 나온다. 모델이 어떻게 생각하고 있는지를 들여다볼 수 있는 구조가 디자이너 입장에서는 꽤 흥미로웠다.

벤치마크 중에서 Terminal Bench 4.1 점수가 기반 모델 대비 5.6%에서 12.0%로 올랐다. 터미널에서 직접 명령을 실행하고 결과를 보면서 작업을 완료하는 능력이 두 배 가까이 올랐다는 얘기다.

## 2️⃣ 내가 든 생각

학습 인프라 쪽이 예상보다 복잡했다. 추론용 GPU 128개와 학습용 GPU 16개를 비동기로 나눠 쓴다. 모델이 환경 안에서 직접 행동하면서 데이터를 만들고, 그 데이터를 동시에 학습에 쓰는 구조인 것 같다. 이게 왜 효율적인지를 생각해보니, 모델이 쉬지 않고 계속 행동해야 하니 추론 쪽에 GPU를 더 많이 써야 하는 것 같다는 추측이 들었다.

👉🏻 샌드박스를 직접 운영했다는 게 가장 의외였다. 약 94만 개의 샌드박스를 최대 1,566개 동시에 돌리면서 9주간 성공률 99% 이상을 유지했다고 한다. 에이전트 학습이 단순히 GPU와 데이터의 문제가 아니라, 모델이 실제로 행동할 수 있는 환경 전체를 설계하는 일이기도 하다는 게 공부하면서 든 생각이었다.

> 💡 **여기서 드는 질문?**
> 포스트 트레이닝으로 성능을 이만큼 올릴 수 있다면, 기반 모델의 크기보다 어떻게 학습시키느냐가 더 중요해지는 시점이 있을까?

디자이너 관점에서 보면 "약점을 타겟으로 한 데이터 큐레이션"이 가장 인상적이었다. 사용자 테스트에서 약점을 찾고 그 부분을 개선하는 흐름이랑 발상이 비슷하게 느껴졌다. 단순히 더 많은 데이터를 모으는 게 아니라, 기존 모델이 어디서 무너지는지를 먼저 파악하고 그걸 집중적으로 반복하는 방식이라는 점이 조금 낯설고 흥미로웠다.

## 3️⃣ 더 살펴보고 싶은 부분

에이전트 모델이 나올 때마다 "에이전트 작업을 잘한다"는 게 실제로 어떤 의미인지가 궁금해진다. Terminal Bench 점수가 올랐다는 게 발표에서는 가장 직관적인 지표로 나왔는데, 터미널 명령 실행 능력이 실제 개발 흐름에서 어떻게 작동하는지는 문서만 본 입장에서는 아직 잘 모르겠다.

Miles 같은 강화학습 포스트 트레이닝 도구가 오픈소스로 공개되는 흐름도 계속 눈여겨봐야 할 것 같다. 에이전트 학습을 위한 인프라가 점점 접근 가능해지는 건지, 아직은 대형 팀의 영역인 건지 — 지금 단계에서 정리해보면 아직은 후자에 가까운 것 같다.

## ⭐️ 마지막으로, 개발자 도구 공부에서 계속 드는 질문

이런 류의 발표를 볼 때 자꾸 같은 질문을 하게 되는 것 같다 — 더 큰 모델을 만드는 것과, 같은 크기의 모델을 더 잘 훈련하는 것 사이에서 지금 업계는 어느 쪽에 더 무게를 두고 있을까. DaisyRose-27B 발표가 그 질문에 대한 하나의 대답처럼 읽혔다.
