Figma 블로그에서 1Password 디자인 팀의 케이스 글을 읽었다. Figma Make를 어떻게 쓰는지를 다룬 글이었는데, 처음엔 도구 홍보글 정도로 생각하고 열었다.

읽어보니 도구 자체 설명보다 그걸 쓰기 위해 사전에 세팅한 것들이 더 오래 머릿속에 남았다.

## 1️⃣ 이게 뭐냐?

Figma Make는 프롬프트를 입력하면 UI를 생성해주는 Figma AI 기능이다. 베타를 거쳐 일반 공개됐고, 1Password 팀은 이 도구를 도입하면서 먼저 코드 기반 플레이그라운드를 세팅했다.

제품 코드 템플릿을 담은 프론트엔드 전용 저장소다. Figma 파일과 실제 제품 레퍼런스에서 뽑아낸 거다. 여기에 Code Connect도 엮었다. Code Connect는 플레이그라운드의 코드 컴포넌트를 Figma 라이브러리 컴포넌트와 매핑하는 방식이다. 예를 들어 Primary 버튼을 Secondary로 바꾸는 걸 드롭다운 하나로 할 수 있게 된다.

디자인 시스템 가이드도 AI가 참조할 수 있는 형태로 정리했다. 콘텐츠 디자인 원칙, 타이포그래피 선택 이유, 컴포넌트 사용 맥락 같은 것들을 사람이 읽는 문서로 두지 않고, 도구와 에이전트가 읽을 수 있게 만든 거다. 1Password 자체 MCP를 채팅에 연결해서 설계 대화 상대로 쓴다는 내용도 있었다.

## 2️⃣ 내가 든 생각

가장 흥미로웠던 부분은 "디자인 시스템 가이드를 AI 컨텍스트로 만든다"는 접근이었다. 디자인 시스템 문서는 사람이 읽는 거라고 막연히 생각하고 있었는데, 이 케이스에서는 AI가 참조하는 레퍼런스로 쓰이고 있었다. 타이포그래피를 왜 그렇게 골랐는지, 컴포넌트 사용 맥락이 뭔지를 AI에게 설명한다는 발상이 어색하면서도 자연스럽게 느껴졌다.

글에서는 수정 작업 대부분을 Figma Make가 맞췄다고 했다. 완벽하진 않았지만 그 비율보다 "무엇을 맞추냐"가 더 중요할 것 같았다. 하드코딩된 패딩 값을 디자인 시스템 변수로 교체하는 반복 작업을 AI가 대신 처리해준다는 게, 단순 자동화 이상의 의미인 것 같았다.

👉🏻 코드 레이어를 Figma 캔버스에 올린다는 것도 처음 보는 방식이었다. 코딩된 프로토타입이 Figma 파일 안에 들어가는 형태인데, 에이전트가 클릭 흐름을 추적해서 아트보드를 만들어준다고 했다. Figma 안에서 코드와 디자인이 같은 파일 안에 존재하게 되는 셈이다.

> 💡 **여기서 든 질문**: 디자인 시스템 가이드를 "문서"로 관리하던 방식이, AI 도구가 보편화되면 어떤 형태로 바뀔까?

## 3️⃣ 공부한 입장에서 보면

글을 읽으면서 Figma Make를 "쓰는 법"보다 "준비하는 법"이 더 비중을 차지한다는 인상을 받았다. 플레이그라운드 세팅, Code Connect, AI용 컨텍스트 정리. 이 사전 작업들이 없으면 프롬프트만 넣는 도구로 끝났을 것 같다.

디자이너가 코드 플레이그라운드를 세팅하고 디자인 원칙을 AI용 형태로 정리한다는 흐름이, 디자이너의 작업이 조금씩 다른 방향으로 옮겨가고 있는 것처럼 느껴졌다.

## ⭐️ 마지막으로, 디자인 도구 공부하면서

이런 류의 케이스를 볼 때마다 자꾸 같은 질문이 생긴다 — 도구를 잘 활용하는 팀과 그렇지 않은 팀의 차이가, 결국 도구보다 사전 준비에 있지 않을까.
