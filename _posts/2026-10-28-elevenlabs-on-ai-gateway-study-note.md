Vercel 블로그에 ElevenLabs 관련 발표가 올라왔다. AI Gateway에 오디오 모델 14개가 추가됐다는 내용인데, 처음엔 모델 목록 하나 더 늘었나 싶었다.

읽어보니 구조가 조금 달랐다. 음성 인식부터 실시간 에이전트, 음악 생성까지 오디오 작업 전반을 단일 게이트웨이로 묶겠다는 방향이었다. 이게 어떻게 동작하는지 정리해봤다.

## 1️⃣ AI Gateway가 오디오를 묶는 방식

AI Gateway는 여러 AI 모델을 하나의 API 키로 호출할 수 있게 해주는 Vercel의 서비스다. 여기에 이번에 ElevenLabs 오디오 모델 14개가 들어왔다. 기존에 텍스트 중심이던 게이트웨이에 음성 레이어가 붙는 모양새였다.

지원 유형은 여섯 가지다. 음성 인식(STT), 스트리밍 TTS, 실시간 음성 에이전트, 음악 생성, 효과음 생성, 다중 화자 대화. 모두 동일한 API 키 하나로 연결되고, 사용량과 비용도 같은 대시보드에서 추적된다.

발표에 나온 파이프라인을 따라가보면 이렇다. AI SDK의 `streamTranscribe`로 사용자 음성을 텍스트로 바꾸고, `streamText`로 LLM이 응답을 생성하고, `streamSpeech`로 그 응답을 음성으로 내보낸다. 핵심은 각 단계가 독립된 모델이라는 것인데, STT나 LLM이나 TTS 어느 쪽이든 나머지를 건드리지 않고 교체할 수 있는 구조다.

## 2️⃣ 공부하면서 흥미로웠던 부분

디자이너 관점에서 음성 인터페이스를 생각할 때, 기존엔 STT, LLM, TTS를 각기 다른 서비스에서 가져와 연결하는 과정이 번거로웠다. 서비스마다 API 키를 따로 관리하고 비용도 따로 봐야 했는데, 이 발표는 그 연결 레이어를 하나로 정리하겠다는 방향으로 읽혔다.

👉🏻 각 단계가 독립적이라는 점이 특히 인상적이었다. TTS 모델만 바꾸거나 LLM만 교체할 때 파이프라인 전체를 건드리지 않아도 된다는 구조니까.

실시간 음성 에이전트 부분도 살펴봤다. `useRealtime`이라는 React 훅을 쓰는데, 서버에서 토큰과 WebSocket URL을 받아 세션을 여는 흐름이었다. 문서에서 본 예제 코드가 생각보다 단순해 보였는데, 인식·추론·음성 출력을 따로 연결하지 않고 세션 하나로 묶는다는 방식이 처음 접하는 입장에선 구조를 파악하기 쉬울 것 같다는 생각이 들었다.

> 💡 **여기서 드는 질문?**
> 각 단계가 독립 모델이라는 게 유연성 면에서 장점이지만, 단계마다 레이턴시가 쌓이지 않을까? 발표 본문에선 Flash v2.5가 낮은 레이턴시를 목표로 설계됐다고 나오는데, 공부한 내용만으로는 실제 체감이 어느 정도인지 가늠이 안 됐다.

다중 화자 대화 기능도 처음 봤다. 화자별 음성을 배열로 넘기면 하나의 연속된 오디오 파일이 나오는 구조였다. 클립을 따로 만들어 이어 붙이는 방식이 아니라 대화 전체를 한 번에 요청할 수 있다는 게 흥미로웠는데, 문서만 봐서는 실제로 어떻게 들리는지 감은 안 잡혔다.

## 3️⃣ 공부한 내용 기준으로 인상적이었던 것

음악 생성과 효과음도 같은 `generateSpeech` 방식으로 호출한다는 게 재밌었다. 텍스트로 원하는 소리를 설명하면 오디오가 나오는 구조인데, 인터페이스 사운드나 루프 배경음을 이런 식으로 만드는 게 어느 수준의 품질인지는 공부만 해봐선 가늠이 안 됐다.

오디오 레이어가 텍스트 레이어와 같은 API 패턴으로 추상화돼 있다는 점이 인상적이었다. AI SDK에서 이미 `streamText`를 쓰고 있다면 오디오를 붙이는 방식도 크게 다르지 않아 보였다. 서비스를 새로 배울 필요 없이 같은 패턴으로 오디오 기능을 더할 수 있다는 건 나름 설득력 있는 설계 방향이었다.

## ⭐️ 마지막으로, 프론트엔드 공부 중인 입장에서

이런 통합 레이어를 볼 때마다 자꾸 같은 질문을 하게 되는 것 같다 — 편의성이 올라갈수록, 각 레이어가 어떻게 작동하는지 직접 이해할 기회는 줄어드는 건 아닐까.
