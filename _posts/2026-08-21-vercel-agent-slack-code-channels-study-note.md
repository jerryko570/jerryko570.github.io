Vercel 공식 블로그에서 Vercel Agent가 Slack 코드 채널에서 동작하기 시작했다는 발표를 봤다. Slack에 "코드 채널"이라는 새 채널 유형이 생겼다는 것도 이번에 처음 알았다. 짧은 공지였는데, 읽다 보니 팀 단위 AI 협업이 실제로 어떤 모양인지가 궁금해져서 정리해봤다.

Vercel Agent는 배포 환경 위에서 동작하는 AI 에이전트다. 코드 변경, PR 리뷰, 인프라 설정 같은 작업을 에이전트에게 맡길 수 있는 구조인 것 같다. 이번 발표는 그 에이전트가 팀 Slack 채널 안으로 들어온다는 내용이었다.

## 1️⃣ 이게 뭐냐?

Slack이 "코드 채널(code channel)"이라는 새 채널 유형을 만들었다. 기존 채널과 비슷하지만 코딩 에이전트와 협업하는 용도로 설계된 채널이고, Vercel Agent가 지원 에이전트로 들어갔다.

채널을 만드는 방법은 단순하다. Slack 사이드바에서 코드 채널 생성을 선택하고 Vercel을 에이전트로 고르면 된다. 기존 채널이나 스레드에서 논의하던 맥락이 있으면 코드 채널로 그대로 이어갈 수도 있다고 한다. 그 대화 내용이 에이전트에게 그대로 전달되는 방식이다.

채널 안에서 Agent는 관련 배포 현황, 로그, 에러, diff 같은 정보를 직접 채널에 올려준다. 팀이 추가 지시를 주거나 PR 리뷰를 요청할 수 있고, 리뷰는 diff 바깥의 버그도 발견할 수 있다고 한다.

기본 설정은 읽기 전용이고, 변경이 필요할 때는 Agent가 먼저 계획을 제안하고 승인을 기다린다. 누가 요청하고 누가 승인했는지, 에이전트가 뭘 실행했는지가 모두 기록된다. 채널을 만든 사람은 작업을 중간에 멈출 수도 있다고 한다.

## 2️⃣ 내가 든 생각

흥미로웠던 건 "팀 채널"이라는 공간 안으로 에이전트가 들어온다는 점이었다. 기존에 AI 에이전트를 쓰는 방식은 대부분 개인 단위였다. IDE 안에서, 터미널에서, 1:1 대화창에서. 그게 팀 채널로 옮겨가면 어떤 모양일지가 좀 궁금했다.

👉🏻 "팀 전체가 에이전트의 작업 흐름을 볼 수 있다"는 부분이 인상적이었다. 에이전트가 뭘 하고 있는지를 팀이 함께 본다는 게 기존 방식과 다른 지점인 것 같다. 공부한 내용 기준으로는, AI 작업의 가시성이 팀 단위로 올라간다는 게 핵심인 것 같다.

> 💡 **여기서 드는 질문?**
> 팀원들이 에이전트에게 각자 지시를 줄 수 있다면, 어떤 기준으로 우선순위를 정하는 걸까?

승인 체계가 있다는 점도 생각이 좀 들었다. 에이전트가 스스로 뭔가를 바꾸는 게 아니라, 계획을 내놓고 사람이 허락해야 진행하는 구조다. 배포처럼 민감한 작업을 다루는 도구라 그런 것도 있겠지만, 팀 안에서 에이전트에 대한 신뢰를 만들어가는 방식으로도 읽혔다.

디자이너 관점에서 보면 "채널"이라는 인터페이스가 흥미롭다. 별도의 툴 없이 평소 쓰던 Slack이 AI 에이전트와의 협업 창구가 된다는 것. 채널이라는 익숙한 형식 안에 에이전트가 녹아드는 방향인 것 같다.

## 3️⃣ 앞으로 어떻게 쓸까?

지금 단계에서 정리해보면, 팀 단위로 AI 에이전트를 쓰는 시나리오가 점점 구체화되는 것 같다. 개인 단위의 AI 코딩 도구는 이미 익숙해지는 편인데, 팀 전체가 같은 에이전트를 두고 협업하는 방식은 아직 낯선 편이다.

채널이라는 공간을 쓴다는 게 UI 관점에서도 흥미롭다. 에이전트와의 상호작용을 별도 인터페이스로 만들 수도 있는데, 기존 메시징 채널 안으로 녹이는 선택을 한 것이다. 그게 팀 채택 과정에서 어떤 차이를 만드는지는 공부한 내용만으로는 잘 모르겠다.
