Figma 블로그에서 Code layers가 오픈 베타로 출시됐다는 글을 읽었다. Config India 행사에서 여러 기능을 한꺼번에 발표했는데, 그 중에서 Code layers가 제일 눈에 들어왔다.

캔버스 위에서 코드가 산다는 게 처음엔 잘 그려지지 않았다. 발표 글을 꼼꼼히 읽어보니 생각보다 구체적인 개념이 있어서 공부한 내용을 정리해봤다.

## 1️⃣ 이게 뭐냐?

지금까지 Figma 캔버스에는 디자인 레이어만 올릴 수 있었다. 실제 동작하는 코드 프로토타입은 Cursor나 VSCode 같은 환경에서 따로 작업해야 했고, 팀과 공유하려면 배포 링크를 별도로 보내야 하는 일이었다.

Code layers는 그 코드 기반 프로토타입을 캔버스 위로 가져오는 기능이다. 디자인 레이어 옆에 코드로 돌아가는 프로토타입이 같은 화면에 나란히 앉는 구조가 된다.

만드는 방법은 여러 가지다. 기존 Figma 디자인을 동작하는 코드로 변환하거나, GitHub 레포에서 직접 불러오거나, Chrome 확장 프로그램으로 라이브 웹페이지를 캡처할 수도 있다. Figma MCP 서버를 통해 코딩 툴에서 만든 프로토타입을 캔버스로 끌어오는 것도 된다.

👉🏻 GitHub에서 가져온 경우, 레이어가 해당 레포와 계속 연결된 상태가 유지된다. 변경 사항을 브랜치에 푸시하고 PR로 팀이 검토하는 것도 Figma 안에서 가능하다고 한다. 기존 개발 흐름과 꽤 자연스럽게 이어지는 구조인 것 같다.

올라온 코드 레이어를 수정할 때는 Figma 에이전트에 프롬프트를 입력하는 방식이다. 예를 들어 지도 클러스터 기능을 추가해달라고 요청하거나, 프레임에 주석을 달아 에이전트에 수정 위치를 알려주는 것도 된다고 한다. 코드를 직접 보거나 편집하는 것도 가능하지만, 꼭 그래야 하는 건 아닌 것 같았다.

> 💡 **여기서 드는 질문 —** 코드 레이어가 캔버스에 올라오면 디자이너와 개발자의 작업 범위가 어떻게 달라질까?

## 2️⃣ 내가 든 생각

디자이너 입장에서 보면, 이건 "코드를 알아야 한다"의 압박보다 "코드 결과물이 디자인 공간으로 들어온다"는 쪽에 더 가까운 것 같다.

이전까지 프로토타입은 두 세계로 나뉘어 있었다. Figma의 클릭 프로토타입과, 실제 동작하는 코드 빌드. 둘을 같이 보려면 둘 다 따로 열어야 했다. Code layers는 그 간격을 캔버스 안에서 줄이려는 시도로 읽혔다.

특히 흥미로웠던 건 `Extract designs` 기능이다. 코드 레이어의 화면이나 플로우를 편집 가능한 Figma 레이어로 꺼낼 수 있는 것이다. 코드 → 디자인 방향의 흐름인데, 이게 잘 돌아간다면 디자인 파일이 늘 코드보다 앞서거나 뒤처지는 문제가 좀 달라질 것 같다는 생각이 들었다.

에이전트에 프롬프트를 입력해 코드 레이어를 수정하거나, 여러 에이전트 스레드를 동시에 돌리면서 방향을 나란히 비교하는 것도 된다고 한다. 발표 내용 기준으로는, 초기 탐색 단계에서 여러 방향을 병렬로 벌리는 용도로 쓰일 것 같았다.

코드 레이어를 복제해서 나란히 두고 비교하는 것도 가능한데, 이 부분이 디자이너로서 꽤 와닿는 구조였다. Figma에서 아트보드 여러 개를 두고 디자인 방향을 비교하는 것처럼, 코드 기반 프로토타입도 그렇게 다룰 수 있게 된다는 것이다. 디자인 레이어와 코드 레이어가 다른 방식으로 만든 같은 화면을 보여주는 상황도 생길 수 있을 것 같다는 생각이 들었다.

## ⭐️ 마지막으로, 디자인-개발 경계를 공부하며 느낀 점

정리해보니 Code layers는 디자이너가 코드를 더 알아야 하는 기능이 아니라, 코드가 디자인 공간으로 들어오는 기능에 가까웠다. 책임의 방향이 뒤집혀 있는 것이다.

이런 류의 도구를 볼 때 자꾸 같은 질문을 하게 되는 것 같다 — 캔버스가 점점 더 많은 것을 품을수록, 디자이너는 결국 뭘 결정하는 사람이 되는 걸까.
