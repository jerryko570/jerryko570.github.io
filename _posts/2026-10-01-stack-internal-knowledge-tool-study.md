Stack Overflow 블로그에서 Stack Internal의 일반 공개 소식이 올라왔다. 처음엔 그냥 기업용 내부 Q&A 시스템 정도로 생각했는데, 읽다 보니 MCP Server 연결 부분이 꽤 흥미롭게 느껴졌다. 좀 더 제대로 정리해보고 싶어서 공부해봤다.

기존까지 Stack Internal은 기업 고객 중심으로만 운영됐다고 한다. 이번 발표에서 바뀐 건 누구나 무료 Starter 워크스페이스를 시작할 수 있게 됐다는 것이다.

## 1️⃣ 이게 뭐냐?

한마디로 하면, 팀이 매일 하는 작업에서 지식을 자동으로 끌어모아 AI가 쓸 수 있는 형태로 저장해두는 도구인 것 같다. Slack, Microsoft Teams, Google Docs 같은 곳에서 이미 오가는 대화와 문서를 수집해서, 정제된 지식 베이스로 만드는 게 목표다.

SME(Subject Matter Expert) 자동 감지 기능도 있다. 특정 주제를 잘 아는 팀원을 알아서 찾아내고, 그 사람이 수집된 내용을 검증하는 워크플로우로 이어준다고 한다. 지식의 정확성을 사람이 보증하는 구조를 자동화하려는 시도처럼 읽혔다.

👉🏻 흥미로웠던 건 MCP Server 연결이다. Claude나 Cursor 같은 AI 도구가 이 지식 베이스에 직접 접근할 수 있게 된다는 뜻이다. AI 에이전트가 꺼내 쓸 수 있는 메모리로 팀 지식을 만들겠다는 방향인 것 같다.

API도 v3로 업그레이드됐다. 저자 정보를 보존하면서 콘텐츠를 이전하거나, 배지나 사용자 활동 필터를 쿼리할 수 있는 엔드포인트가 추가됐다고 한다.

> 💡 **여기서 드는 질문?**
> SME 자동 감지가 실제로 얼마나 정확할까. 자동으로 찾아낸 전문가가 항상 맞는 사람이라는 가정이 좀 낙관적이지 않을까 싶기도 했다.

## 2️⃣ 내가 든 생각

디자이너 입장에서 보면, 이 도구가 다루려는 문제는 꽤 오래된 것이다. 슬랙 대화에 묻힌 결정 사항, 문서 어딘가에 흩어진 배경 이유, 퇴사한 팀원만 알고 있던 맥락 같은 것들. 그게 사라지지 않게 잡아두고 싶다는 욕구는 팀이라면 어디든 비슷하게 있는 것 같다.

근데 이번에 다르게 느껴진 건 방향이었다. 단순히 검색 가능한 위키를 만드는 게 아니라, AI 에이전트가 직접 꺼내 쓸 수 있는 형태로 만들겠다는 목표인 것 같다. MCP 연결이 핵심이고, 그게 Stack Internal을 단순 지식 저장소와 구분 짓는 지점처럼 느껴졌다.

이번 공개 출시에 맞춰 커스텀 역할, 권한 관리, 감사 추적 같은 거버넌스 기능도 대폭 늘어났다고 한다. 무료 플랜을 열면서 동시에 기업 기능을 강화했다는 건, 소규모 팀을 입구로 삼아 위로 끌어올리려는 전략에 가까운 것 같다. 그 패턴은 다른 도구에서도 많이 봤던 것이라 낯설지는 않았다.

## ⭐️ 마지막으로, 팀 지식 관리 도구를 공부하며

이런 류의 도구를 볼 때 자꾸 같은 질문을 하게 되는 것 같다 — 지식이 "흐른다"는 게 결국 어떤 상태를 말하는 건지.

저장은 오래됐고, 검색도 이제 AI가 해준다. 근데 그게 팀이 실제로 쓰는 방식까지 이어지려면 도구가 워크플로우에 자연스럽게 녹아있어야 할 것 같다. Slack/Teams 커넥터와 MCP 연결이 노리는 게 그 지점인 것 같고, 그게 잘 되는지는 공부한 내용 기준으로는 아직 판단이 서지 않는다.
