Webflow 공식 블로그에서 MCP 서버 업데이트 소식이 올라왔다. 제목을 보니 Interactions, agent instructions, Cloud deploys가 한꺼번에 들어가 있어서 각각 뭘 의미하는 건지 궁금해서 읽어봤다.

MCP는 AI 에이전트가 Webflow 사이트를 직접 조작할 수 있게 해주는 프로토콜이다. 이번 업데이트 전까지는 레이아웃 구성 정도가 전부였다고 하는데, 이번에는 에이전트가 다룰 수 있는 범위가 꽤 달라진 것 같았다. 어떤 식으로 달라졌는지 하나씩 정리해봤다.

## 1️⃣ 이게 뭐냐?

이번에 추가된 기능은 크게 세 가지다.

첫 번째는 Interactions 패널 애니메이션 생성이다. 에이전트가 스크롤 트리거, 마우스 추적, 텍스트 분리 같은 UI 애니메이션을 직접 만들 수 있게 됐다. GSAP 기반으로 구현되고, 에이전트가 생성한 결과물이 Webflow Interactions 패널에 바로 올라가서 거기서 수정도 할 수 있다고 한다. 에이전트가 초안을 잡으면 사람이 이어받아 다듬는 방식이 되는 거다.

두 번째는 에이전트 인스트럭션 자동 생성이다. 사이트의 색상 팔레트, 타이포그래피, 컴포넌트 구조를 분석해서 에이전트가 따를 규칙 문서를 자동으로 만들어준다. 작업자가 직접 검토한 뒤 MCP 스킬로 저장해두면, 이후 어떤 작업을 시켜도 에이전트가 기존 스타일을 유지하면서 작업할 수 있게 된다.

세 번째는 Webflow Cloud 앱 배포다. 에이전트가 소스코드를 수정하고, Git 푸시, 배포 완료 대기, 결과 검증까지 직접 처리한다. 빌드 로그도 읽고, 에러가 나면 자동 롤백까지 할 수 있다고 한다.

## 2️⃣ 내가 든 생각

디자이너 입장에서 가장 눈에 띈 건 Interactions 부분이었다. 애니메이션은 타이밍이나 트리거 설정처럼 직접 손봐야 하는 영역이라고 생각했는데, 에이전트가 생성하고 패널에서 수정까지 된다는 게 조금 다른 방식이었다. 사람이 처음부터 만드는 게 아니라, 에이전트가 초안을 잡으면 사람이 감수하는 흐름에 가까운 거다.

에이전트 인스트럭션 자동 생성 기능은 접근 방식이 흥미로웠다. 보통 에이전트한테 작업을 시킬 때 색상 코드나 폰트 규칙을 매번 직접 알려줘야 한다. 근데 이건 사이트 구조를 분석해서 규칙을 자동으로 뽑아낸다는 거다. 디자인 시스템을 따로 문서화하지 않아도 에이전트가 기존 패턴을 스스로 파악한다는 방향인 것 같다.

👉🏻 세 기능이 각각 따로 있다기보다, 에이전트가 사이트를 이해하고 기준을 정리하고 구현까지 잇는 흐름으로 묶인다는 게 이번 업데이트의 방향인 것 같다.

> 💡 **여기서 드는 질문?**
> 에이전트가 자동 생성한 인스트럭션이 실제 디자이너가 의도한 규칙과 얼마나 일치할까? 색상이나 폰트는 뽑을 수 있겠지만, 암묵적으로 정한 예외 케이스 같은 건 어떻게 처리하는지 지금은 잘 모르겠다.

## ⭐️ 마지막으로, 공부하며 든 생각

정리해보니 이번 업데이트의 핵심은 기능 숫자보다 흐름 쪽에 있는 것 같다. 애니메이션 생성, 가이드라인 추출, 배포 처리가 각각 독립적인 기능이라기보다는, 에이전트가 사이트를 맥락 안에서 다루는 방식으로 묶인다는 느낌이었다. 그게 실제로 어떻게 작동하는지는 공부만 해본 입장에서는 아직 가늠이 잘 안 된다.
