Vercel 블로그에서 eve 1.0 정식 출시 발표가 나왔다. 올해 6월에 미리보기로 나왔던 에이전트 프레임워크인데, 이번에 1.0으로 GA가 됐다. 이전에 구조를 한 번 공부한 적이 있어서, 1.0에서 뭐가 달라졌는지가 궁금했다.

발표 자료를 보니 단순히 "안정화" 수준이 아니었다. 성능과 아키텍처 모두 꽤 바뀐 것 같았고, 미리보기 때는 없었던 기능도 여럿 추가됐다.

## 1️⃣ 1.0에서 뭐가 달라졌나?

가장 눈에 들어온 건 아키텍처 변화였다. 미리보기 때는 단계마다 대화 전체를 복사해서 저장했는데, 1.0부터는 변경된 부분만 저장하는 방식으로 바뀌었다. 덕분에 응답 지연이 많이 줄고, 긴 세션의 비용도 낮아졌다고 한다.

도구 목록도 달라졌다. 처음부터 모든 도구를 프롬프트에 넣는 방식에서, 필요할 때 로드하는 방식으로 바뀌었다. 도구가 많아질수록 초기 프롬프트가 무거워지는 문제를 개선한 것 같다.

Workflow SDK는 에이전트가 작업하면서 상태를 저장해 준다. 크래시가 나도 마지막으로 완료된 단계부터 이어서 시작할 수 있다. 에이전트끼리 서로 호출하는 것도 기본으로 들어있다.

트레이싱이 OpenTelemetry 기반으로 재구축된 것도 달라진 부분이었다. 승인 대기·질문·모델 비용까지 추적하고, 수집 항목을 직접 필터링하거나 입출력을 가릴 수 있다고 한다. 채널 지원도 Slack, Discord, Teams, GitHub, Linear 등 여러 곳을 네이티브로 지원하고, 각 채널은 파일 하나로 구성된다.

시작 방법도 간단하다. Node.js 24 이상이면 `npx eve@latest init`으로 프로젝트를 만들 수 있다고 한다. Vercel 대시보드에서 바로 시작하거나 용도별 템플릿을 쓸 수도 있다.

## 2️⃣ 내가 든 생각

"하네스를 직접 소유한다"는 표현이 발표에서 꽤 강조됐다. 에이전트가 돌아가는 루프—모델 호출, 도구 실행, 서브에이전트 위임—를 개발자가 직접 코드로 갖는다는 얘기다. 프레임워크가 이걸 감추거나 고정하지 않는다는 점이 특이하게 느껴졌다.

👉🏻 디자이너 입장에서 흥미로웠던 건 "승인 설계"였다. 어떤 작업은 사람이 확인해야 넘어가고, 어떤 작업은 자동으로 흐른다—그 경계를 코드로 정의한다. UI에서 말하는 "컨트롤 포인트" 설계랑 비슷한 발상이라는 생각이 들었다.

멀티플레이어 세션도 눈에 들어왔다. Slack 스레드 하나가 하나의 공유 세션이 되어, 여러 사람이 같은 에이전트 흐름 안에서 대화한다. 승인 버튼도 메시지 형태로 붙는다. 에이전트를 혼자 쓰는 도구가 아니라 팀 단위로 설계했다는 인상이었다.

> 💡 **여기서 든 질문?**
> 하네스를 직접 소유한다는 게 실제로 얼마나 복잡할까. 자유도가 높아지면 그만큼 설계에서 고민해야 할 것도 늘어날 텐데.

Extensions도 1.0에서 추가됐다. 도구, 채널, 스킬을 파일 복사 없이 패키지 형태로 공유할 수 있는 방식이다. 에이전트 코드가 협업 단위로 나뉘는 발상이 좀 낯설었다.

## 3️⃣ 더 살펴보고 싶은 부분

멀티테넌트 지원도 있다. 테넌트별로 메모리, 연결 자격 증명, 승인 정책을 따로 관리한다고 한다. 여러 고객이 같은 에이전트를 쓰는 프로덕트를 만들 때 필요한 부분인 것 같다.

메모리 기능도 흥미로웠다. 세션 간 대화 맥락을 유지해 주는데, 사용자가 이전에 했던 말을 에이전트가 이어받는 셈이다. 이게 사용자 경험에서 어떻게 느껴질지도 디자이너 입장에서는 궁금한 부분이다.

## ⭐️ 마지막으로, eve 1.0을 공부하고 나서

정리해보니 에이전트 프레임워크 공부가 "어떤 모델을 쓰느냐"를 고르는 일보다, "에이전트가 뭘 하게 허용할지"를 설계하는 일에 가까운 것 같다. 프레임워크가 추상화하는 게 모델 호출 자체가 아니라, 에이전트 행동의 경계라는 발상이 공부 끝에 남은 인상이다.
