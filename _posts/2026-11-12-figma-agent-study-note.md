Figma 공식 블로그에서 Agent 관련 글이 올라왔다. "지금 당장 활용하는 6가지 방법"이라는 제목이었는데, 구체적인 사용 사례들이 나열되어 있었다.

읽으면서 궁금했던 건 하나였다. 캔버스 안에서 에이전트가 직접 움직인다는 게 기존 플러그인과 뭐가 다른 걸까? 그 차이를 이해해보려고 정리해봤다.

## 1️⃣ 이게 뭐냐?

Figma Agent는 캔버스 안에서 직접 작동하는 AI 도구다. 플러그인처럼 별도 패널이 아니라 캔버스 맥락 그대로 명령을 받고 디자인을 수정하거나 생성한다.

글에서 소개된 활용법은 크게 세 방향으로 묶인다.

첫 번째는 **정리 작업 자동화**다. 회의록이나 Notion 문서를 커넥터로 연결하면 에이전트가 관련 프레임 옆에 피드백 주석을 달아준다. `/comments-do-try-consider` 스킬을 쓰면 코멘트를 '할 일/시도/고려'로 분류해준다. 리뷰 후 액션 아이템을 정리하는 시간이 줄 것 같다는 인상을 받았다.

두 번째는 **탐색 단계 가속화**다. 프롬프트 하나로 여러 레이아웃 변형을 동시에 만들어준다. 팀 라이브러리를 연결하면 기존 컴포넌트, 스타일, 변수를 그대로 써서 생성한다고 한다. 맥락 없이 생성하는 게 아니라 디자인 시스템 안에서 작동한다는 점이 흥미로웠다.

세 번째는 **기술적으로 복잡한 작업 위임**이다. 셰이더 효과 생성, 코드 기반 프로토타입, 모션 추가가 여기 해당한다. 정적 디자인에 "Build this with code"를 붙이면 에이전트가 카드 스와이프 같은 인터랙션을 코드로 만들어준다고 한다.

## 2️⃣ 내가 든 생각

가장 흥미로웠던 건 탐색 단계 이야기였다. 디자인 초반에 여러 방향을 캔버스에 펼치는 작업은 보통 조용히 시간을 써야 하는 과정인데, 그게 프롬프트 하나로 가능해진다면 작업 흐름이 꽤 달라질 것 같다.

👉🏻 근데 의문이 생긴 부분도 있었다. 라이브러리 없이 쓰면 에이전트가 뭘 기반으로 생성하는 걸까.

라이브러리가 없는 상태에서 여러 변형을 만들면, 나중에 정리하는 작업이 오히려 늘어날 수 있다는 생각이 들었다. 디자인 시스템을 유지하면서 쓰려면 라이브러리 세팅부터 잘 되어있어야 한다는 전제가 붙는 것 같다.

> 💡 **여기서 드는 질문?**
> Figma Agent의 결과물 품질은 팀 라이브러리 품질에 얼마나 의존할까? 라이브러리가 엉성하면 에이전트 결과도 엉성할까?

코드 레이어 기능도 궁금했다. 정적 디자인을 코드 기반 프로토타입으로 만든다는 건 알겠는데, 이게 프로토타입 수준의 코드인지 실제 프로덕션에 가까운 출력인지 글만 봐선 명확하지 않았다. 디자이너-개발자 핸드오프를 어디까지 대체할 수 있을지는 직접 써본 사람의 이야기가 더 필요할 것 같다.

## ⭐️ 마지막으로, 디자인 도구를 공부하면서 느낀 점

이런 AI 기능을 볼 때마다 자꾸 같은 질문을 하게 되는 것 같다 — 이 도구가 디자이너의 판단을 대신하는 건가, 아니면 판단을 더 빨리 내릴 수 있게 돕는 건가.

Figma Agent는 지금 단계에서는 후자에 가까운 것 같다. 글에서도 디자인 통제권은 디자이너가 유지한다고 명시하고 있다. 탐색, 정리, 반복 작업을 줄여주는 쪽이지, 의사결정 자체를 가져가는 건 아닌 것 같다.

공부한 내용 기준으로는 그렇게 받아들이고 있다.
