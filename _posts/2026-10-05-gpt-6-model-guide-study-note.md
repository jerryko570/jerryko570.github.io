OpenAI에서 GPT-6 패밀리 모델 가이드 문서를 공개했다. 스타트업 기준으로 어떤 모델을 고를지, reasoning effort를 어떻게 조정할지, 프롬프트를 어떻게 다듬을지, skills와 tools를 어떻게 조합할지, 그리고 프로덕션 워크플로우까지 어떻게 준비하는지를 다루는 내용이었다.

제목을 봤을 때는 "모델 선택 가이드면 그냥 좋은 거 쓰라는 말 아닌가" 싶었다. 근데 목차를 훑으면서 생각이 좀 달라졌다. 선택지가 있다는 건 그만큼 고민할 게 있다는 뜻이니까.

## 1️⃣ 이게 뭐냐?

GPT-6는 단일 모델이 아니라 패밀리다. 변종이 여럿 있고, 상황에 따라 다른 모델을 고르는 게 낫다는 게 이 가이드의 출발점이다. 속도가 중요한 작업과 정확도가 중요한 작업을 같은 모델로 돌리는 건 비효율적이라는 시각이었다.

가장 흥미로웠던 건 **reasoning effort**라는 개념이었다. 모델이 답을 내기 전에 "얼마나 깊이 생각할지"를 조절하는 파라미터다. 간단한 요청에는 낮게, 복잡한 추론이 필요한 작업에는 높게 잡는 식으로 쓰는 것 같았다. 이게 비용과 응답 속도에도 영향을 준다고 한다.

**Skills**라는 개념도 나온다. 복잡한 워크플로우를 구성할 때 모듈처럼 조합할 수 있는 단위인 것 같았다. Tools와 함께 쓰이면서 여러 작업을 연결하는 흐름을 만들 수 있다고 한다. 지금 이해한 내용 기준으로는, 모델 선택 → reasoning effort 조정 → 프롬프트 최적화 → skills·tools 조합 순서의 흐름이 있는 것 같다.

원문에 직접 접근하지 못해서 세부 내용은 확인하지 못했다. 자세한 건 원문 참고.

## 2️⃣ 내가 든 생각

reasoning effort를 직접 조절한다는 게 좀 새로웠다. 프롬프트를 잘 쓰는 게 전부인 줄 알았는데, 모델의 "생각 깊이"를 파라미터로 다룬다는 발상은 생각해본 적이 없었다. 디자인으로 치면 컴포넌트의 렌더링 비용을 조절하는 것과 비슷한 층위에 있는 것 같기도 했다.

👉🏻 결국 AI 도구를 만든다는 게 API를 연결하는 일이 아니라, 작업의 성격에 맞게 모델을 조율하는 일에 가까워지고 있는 것 같다.

> 💡 **여기서 드는 질문?**
> 모델 선택과 reasoning effort 조정은 개발자가 해야 하는 결정인데, 그러면 AI 기반 인터페이스를 디자인할 때 이 레이어를 어떻게 반영해야 할까?

AI 기반 UI를 공부하다 보면 화면 레이어에서만 생각하게 되는 때가 있다. 근데 모델의 응답 깊이나 처리 속도가 UX에 영향을 준다면, 디자이너도 이 결정에서 완전히 비껴 있을 수는 없겠다는 생각이 들었다. 어디까지 알아야 하는지가 궁금해졌다.

## ⭐️ 마지막으로, 공부하면서 느낀 것

정리해보니, 모델을 고른다는 게 성능 순위표에서 번호를 고르는 일이 아니라 작업의 성격에 맞게 조율하는 일에 가까운 것 같다. 가이드의 맥락이 "스타트업이 프로덕션까지 어떻게 준비하는가"였다는 것도, 모델 선택이 결국 제품 설계의 일부라는 얘기처럼 들렸다.
