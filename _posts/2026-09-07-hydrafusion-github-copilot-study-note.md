GitHub 블로그에서 HydraFusion이라는 이름의 발표가 있었다. GitHub Copilot에 새로 붙은 멀티모델 오케스트레이션 기능인데, 이름이 좀 특이해서 읽어봤다.

Hydra는 머리가 여러 개 달린 신화 속 생물이다. 이름에서 짐작되듯 여러 AI 모델을 상황에 따라 조합해서 쓴다는 개념인 것 같다. 처음엔 그냥 모델 자동 선택 기능인 줄 알았는데, 조금 파보니 구조가 좀 달랐다.

## 1️⃣ 이게 뭐냐?

기존 GitHub Copilot의 Auto 모드는 작업에 맞는 모델 하나를 자동으로 골라줬다. HydraFusion은 거기서 한 발짝 더 나아간 느낌이다. 단일 모델이 아니라 여러 모델의 조합 자체를 런타임에 설계한다.

실행 패턴은 세 가지다. **Single**은 기존이랑 똑같이 모델 하나가 처음부터 끝까지. **Cascade**는 가벼운 모델이 초안을 쓰고, 품질 검증 후 필요하면 더 강력한 모델로 올린다. **Critique**는 모델 A가 작성하고, 다른 모델 B가 독립적으로 검토한 다음, 다시 A가 수정하는 방식이다.

이 패턴 선택을 사람이 하는 게 아니라 HydraFusion이 작업을 분석해서 알아서 정한다는 게 핵심인 것 같다.

현재는 리서치 프리뷰 상태라 GitHub Copilot CLI에서 `/experimental on`으로 활성화하고, `/model`에서 HydraFusion을 지정해야 쓸 수 있다. 공개 배포 전 단계인 만큼 아직 바뀔 여지가 많은 것 같다.

## 2️⃣ 내가 든 생각

처음 읽었을 때 든 생각은, 이게 결국 "비싼 모델을 항상 쓰면 좋은데 현실적으로 그럴 수 없으니 중간 단계를 설계한 것" 아닐까였다. Cascade 패턴이 특히 그런 느낌이다. 먼저 가벼운 모델에게 시키고, 부족하면 더 강한 모델로 올린다는 구조는 비용 문제를 풀려는 접근에 가깝다.

흥미로웠던 건 Critique 패턴이다. 한 모델이 쓰고 다른 모델이 검토한다는 건, 사람이 작업할 때 동료 리뷰를 넣는 것과 비슷한 구조인데, 이걸 모델 조합으로 구현했다는 점이 인상적이었다.

👉🏻 "어떤 모델이 최고냐"가 아니라 "어떤 방식으로 모델을 엮느냐"로 질문의 방향이 조금 이동하고 있다는 느낌이 들었다.

> 💡 **여기서 드는 질문?**  
> Cascade에서 "품질 검증 실패"를 판단하는 기준이 뭘까. 그 기준 자체가 또 다른 모델인지, 룰 기반인지가 공부한 내용에서는 나오지 않아서 궁금해졌다.

## 3️⃣ 앞으로 어떻게 쓸까?

리서치 프리뷰 단계라 아직 많이 바뀔 것 같다는 인상이다. 지금 단계에서 정리해보면, 이 방향이 앞으로 Copilot의 기본 동작 방식에 자연스럽게 녹아들 가능성이 있지 않을까 싶다.

디자이너 입장에서 읽으면서 흥미로웠던 건, 이런 오케스트레이션 설계가 UX 흐름 설계와 비슷하다는 점이었다. 어떤 단계에서 어떤 처리가 필요하고, 어디서 피드백을 받고, 언제 다음 단계로 넘길지. 그 흐름을 AI 모델 간에 적용한 것처럼 읽혔다.

## ⭐️ 마지막으로, 공부하고 남은 한 가지

정리해보니 모델 선택이라기보다 워크플로우 설계에 가까운 일이었다. 어떤 모델이 좋고 나쁘고를 따지는 게 아니라, 어떤 순서로 엮으면 결과가 나아지는가를 설계하는 문제. 공부 끝에 남은 건 그 한 줄짜리 인상이다.
