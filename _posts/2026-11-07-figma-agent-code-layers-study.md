Figma 블로그에서 Workflow lab이라는 시리즈 글이 올라왔다. 코드 레이어와 Figma 에이전트를 써서 여러 안을 캔버스에서 비교하는 워크플로를 소개한 내용이다.

코드 레이어 기능이 오픈 베타로 풀렸다는 얘기는 들었는데, 실제로 어떻게 쓰는 건지 감이 잘 안 왔다. 블로그 글을 읽어보니 조금 정리가 됐다.

## 1️⃣ 이게 뭐냐?

코드 레이어는 Figma 캔버스 위에 실제로 동작하는 코드를 올려두는 개념에 가깝다. 정적인 프레임 목업이 아니라 클릭이 되고 상태가 바뀌는 프로토타입을 Figma 안에서 바로 볼 수 있다는 얘기다.

코드 레이어를 만드는 방법은 여러 가지라고 한다. Chrome 확장 프로그램으로 웹페이지를 캡처하거나, GitHub 저장소를 클론하거나, 프롬프트로 에이전트에게 처음부터 만들어달라고 하는 식이다.

Figma 에이전트를 쓰면 프롬프트 하나로 변형 여러 개를 만들 수 있다. 블로그 예시에서는 "배달 주소 선택 UI 변형 3개"를 요청했더니 주소 검색, 지도 핀 선택, 저장 주소 목록 세 가지 안이 캔버스에 나란히 나왔다고 한다. 코드 레이어를 복제해 하나씩 수정하며 비교하거나, 동료가 만든 안을 에이전트에게 병합 요청하는 것도 가능하다고 한다.

흥미롭게 읽힌 건 Extract designs 기능이었다. 에이전트가 생성한 코드 프로토타입에서 특정 요소를 Figma 디자인 레이어로 꺼내 수정하고, Update code layer로 코드에 다시 반영하는 흐름이 연결된다. 코드를 직접 쓰지 않고도 Figma 도구 안에서 세부 조정이 가능하다는 거다.

## 2️⃣ 내가 든 생각

공부하면서 가장 눈에 띄었던 건 "비교"가 훨씬 쉬워진다는 점이었다. 보통은 여러 도구에서 각각 만든 프로토타입을 링크로 공유하다 보니 나란히 놓고 보기가 번거롭다. 캔버스에 여러 안이 같이 있으면 그 흐름이 달라질 것 같았다.

👉🏻 디자인 레이어와 코드 레이어를 양방향으로 연결하는 부분이 특히 흥미로웠다. 에이전트가 만든 코드를 Figma 도구로 꺼내서 확인하고, 거기서 수정한 걸 다시 코드에 반영하는 구조. 코드를 직접 보지 않아도 되는 레이어가 하나 생기는 것처럼 느껴졌다.

> 💡 **여기서 든 질문**: 에이전트가 생성한 코드는 어느 수준일까? 실제 저장소와 연결되는 코드인지, 프로토타입 전용인지가 궁금해졌다.

정리하다 보니 이 기능이 개인 작업보다는 팀 단위 협업 맥락에서 더 맞을 것 같다는 생각이 들었다. 여러 안을 동료들과 같은 캔버스에서 보고 댓글을 달거나, 의견을 반영해 에이전트에게 병합을 요청하는 흐름. 블로그 글에서 소개된 사례도 디자이너 혼자 완성을 목표로 하는 게 아니라 팀원과 함께 방향을 좁혀가는 과정 중심이었다. 그 맥락이 자연스럽게 느껴졌다.

## ⭐️ 마지막으로, 이 워크플로를 공부하며 든 인상

정리해보니 이 기능의 중심은 코드 프로토타입을 "만드는 것"보다 "비교하고 협의하는 자리에 올려두는 것"에 더 가까운 것 같다. 결국 핵심은 코드 레이어 자체보다 그 코드가 캔버스 위에서 어떤 대화를 가능하게 하는가에 있지 않을까 싶었다.
