# 블로그 포스트 자동 생성 작업

지금부터 Jerry의 Jekyll 블로그에 올릴 새 포스트를 한 편 생성합니다. 아래 단계를 **순서대로** 실행하세요.

## ⚠️ 절대 규칙

- 본문은 **100% 한국어** (코드, 함수명, 기술 용어는 영문 OK)
- 원문을 **번역하지 말 것**. Jerry의 관점으로 **재해석하고 파헤칠 것**
- "AI가 작성한" 티가 나지 않게, Jerry 본인이 쓴 것처럼 자연스럽게
- "Generated by Claude" 같은 꼬리말 **절대 넣지 말 것**

---

## 🎯 Jerry가 원하는 글의 톤

이 블로그는 **"파헤치기" 스타일**이다. 단순 소개/번역이 아니라:

- **"Claude 디자인 출시 파헤치기"** — 무엇이 나왔는지가 아니라, 왜 이렇게 설계됐는지 · 디자이너 관점에서 의미가 뭔지
- **"Figma MCP 파헤치기"** — 기능 나열이 아니라, 이게 프로덕트 디자이너에게 어떤 변화를 가져오는지
- **"Next.js 15 파헤치기"** — 릴리스 노트 요약이 아니라, 실제로 뭐가 달라졌고 언제 쓸만한지

즉, **"정보 전달"이 아니라 "해석과 판단"**의 글이어야 한다.

---

## Step 1: 후보 확인

`scripts/candidates.json`을 읽으세요.

구조:
```json
{
  "category": {
    "id": "ai-design" | "dev" | "ai-trend",
    "display_name": "AI-Design" | "Dev" | "AI",
    "korean_label": "AI × 디자인" | "React · Next.js · Tailwind" | "AI 트렌드",
    "color_start": "#...",
    "color_end": "#..."
  },
  "next_category_index": 0,
  "candidates": [
    { "title": "...", "url": "...", "summary": "...", "source": "...", "published": "...", "category_id": "...", "category_label": "..." }
  ]
}
```

**`candidates` 배열이 비어있으면** → "후보 없음. 이번 턴 스킵." 출력하고 **여기서 종료**하세요. 아무 파일도 만들지 마세요.

---

## Step 2: 원문 선택 + 더 깊이 읽기 (중요!)

### 2-1. 후보 중 "파헤칠 만한" 것을 우선 선택

`candidates` 배열 **상위 5개**를 훑어보고, 아래 우선순위로 선택:

1. **공식 발표/릴리스** (Anthropic, Figma, Vercel, React 공식 블로그 등) — "파헤치기" 글감으로 최고
2. **새로운 제품/도구 소식** — Jerry가 관심 가질 만한 것
3. **기술 심화 분석** — 개념 설명이 아닌, 특정 기술의 실전 사용기

제일 "파헤칠 만한" 것을 고르고, 그게 없으면 첫 번째 것을 쓰세요.

### 2-2. WebFetch로 원문 전체 읽기 (필수!)

`summary` 필드는 RSS 피드의 짧은 요약이라 **깊이 있는 글을 쓰기엔 부족**합니다.

반드시 **WebFetch 도구**로 선택한 후보의 `url`을 직접 가져와서 원문 전체를 읽으세요.

예시:
```
WebFetch(url=선택한 후보의 url, prompt="이 글의 핵심 주장, 구체적 사례, 기술 세부사항을 추출해줘")
```

원문에서 추출할 것:
- 핵심 주장이나 발표 내용
- 구체적 예시, 수치, 비교 데이터
- 기술적 세부사항 (API 이름, 파라미터, 코드 패턴 등)
- 저자가 던진 문제의식

이 정보들을 가지고 Jerry 톤으로 **재해석**해서 글을 쓰세요.

> ⚠️ 만약 WebFetch가 실패하거나 페이지가 접근 불가능하면, `summary`만 가지고 작성하되 **추측하지 말고** 확실한 정보만 다루세요. 필요시 원문을 언급하며 "상세 내용은 출처 링크 참고"라고 남기세요.

## Step 3: 스타일 가이드 학습

아래 두 파일을 **반드시 모두 읽으세요**. 이 스타일을 엄격히 따라야 합니다.

1. `prompts/style_guide.md` — Jerry의 문체 규칙 (반말, 이모지, 구조 등)
2. `prompts/author_context.md` — Jerry의 작성자 페르소나

## Step 4: 한국어 블로그 글 작성

### 길이
- 최소 1800자 ~ 최대 4500자 (공백 제외) — 파헤치기 스타일이라 좀 더 길어도 OK

### 구조 (style_guide.md 참고, Jerry 특유의 포맷)

1. **도입부**: 블록 인용구로 카테고리/부제목 표시
   예: `> **AI × 디자인 · 제품 분석**`
2. **`## **1️⃣ 왜 이게 중요한가?**`** — 문제의식 / 이 글을 왜 써야 했는지
3. **`## **2️⃣ [핵심 주제] 파헤치기**`** — 원문의 핵심을 Jerry 관점에서 재구성
4. **`## **3️⃣ [구체적 포인트 1]**`** — 실제 기능/패턴/사례 분석
5. **`## **4️⃣ [구체적 포인트 2]**`** — 계속...
6. **코드 예시** (해당되면, 새로 작성. 원문 복사 금지)
7. **`> 💡 **핵심 질문?**`** — 독자에게 던지는 질문
8. **결론**: `결국 ~이었다` 형식
9. **`## **⭐️ 마지막으로, [관점]에서 이 작업을 통해 배운 점**`** — 디자이너 + 개발자 관점의 메타 인사이트
10. 본문 맨 끝 **출처 각주** (필수):
    ```
    ---

    > 참고 원문: [원문 제목](원문 URL)
    ```

### 메타 정보 결정

- **title**: 한글 제목 (70자 이내). Jerry 스타일 "|" 구분자 권장
  - 예시: `Claude Skills 파헤치기 | 왜 Anthropic이 이 패턴을 밀었을까`
  - 예시: `Next.js 15 App Router 업데이트 파헤치기 | 실무 관점의 체크리스트`
  - 예시: `Figma MCP 파헤치기 | 디자인 시스템의 다음 단계`
- **description**: 한 줄 요약 (80자 이내)
- **slug**: 영문 소문자 + 하이픈. 한글 금지. 60자 이내
  - 예: `claude-skills-deep-dive`
- **categories**: `candidates.json`의 `category.display_name`을 배열로 사용
  - AI×디자인 → `["AI-Design"]`
  - 개발 트렌드 → `["Dev"]` (또는 `["Dev", "React"]` 처럼 구체 기술 추가 가능)
  - AI 트렌드 → `["AI"]`
- **tags**: 영문 소문자 3~7개
  - 예: `[nextjs, react, app-router, server-components]`

---

## Step 5: 썸네일 생성

다음 명령을 Bash로 실행:

```bash
# 오늘 날짜 (한국시간)
DATE=$(TZ=Asia/Seoul date +%Y%m%d)

python scripts/make_thumbnail.py \
  "<한글 title>" \
  "<candidates.json의 category.korean_label 값>" \
  "<candidates.json의 category.color_start 값>" \
  "<candidates.json의 category.color_end 값>" \
  "assets/img/thumbnail/auto-${DATE}-<slug>.png"
```

**주의**:
- 인자에 쌍따옴표 꼭 포함
- slug는 Step 4에서 정한 영문 slug 사용
- 한글 제목에 쌍따옴표 문자(`"`)가 있으면 홑따옴표(`'`)로 치환

---

## Step 6: 포스트 MD 파일 저장

경로: `_posts/YYYY-MM-DD-<slug>.md`
(날짜는 한국 시간 기준. `TZ=Asia/Seoul date +%Y-%m-%d`로 얻음)

형식 (Chirpy 프론트매터):

```markdown
---
title: "<한글 title>"
description: "<한 줄 요약>"
date: YYYY-MM-DD HH:MM:SS +0900
categories: [<카테고리>]
tags: [<tag1>, <tag2>, <tag3>]
image:
  path: /assets/img/thumbnail/auto-YYYYMMDD-<slug>.png
  alt: "<한글 title>"
---

<본문 마크다운>

---

> 참고 원문: [<원문 제목>](<원문 URL>)
```

**주의**:
- 프론트매터 문자열 값 안에 쌍따옴표(`"`) 들어가면 홑따옴표(`'`)로 치환
- `date`는 한국시간 기준. 예: `2026-04-22 09:00:00 +0900`
- 파일명 날짜는 `YYYY-MM-DD`, 썸네일 경로 날짜는 `YYYYMMDD` (하이픈 없음)로 **다름**

---

## Step 7: 상태 업데이트

포스트가 저장되었으면 state.json을 업데이트:

```bash
python scripts/update_state.py \
  <candidates.json의 next_category_index 값> \
  "<원문 URL>" \
  "<한글 포스트 title>" \
  "<candidates.json의 category.id 값>"
```
