# 블로그 포스트 자동 생성 작업

지금부터 Jerry의 Jekyll 블로그에 올릴 새 포스트를 한 편 생성합니다. 아래 단계를 **순서대로** 실행하세요.

## ⚠️ 절대 규칙

- 본문은 **100% 한국어** (코드, 함수명, 기술 용어는 영문 OK)
- 원문을 **번역하지 말 것**. Jerry의 관점으로 **재해석**해야 함
- "AI가 작성한" 티가 나지 않게, Jerry 본인이 쓴 것처럼 자연스럽게
- "Generated by Claude" 같은 꼬리말 **절대 넣지 말 것**

---

## Step 1: 후보 확인

`scripts/candidates.json`을 읽으세요.

구조:
```json
{
  "category": {
    "id": "frontend",
    "display_name": "Frontend",
    "korean_label": "프론트엔드 개발",
    "color_start": "#3b82f6",
    "color_end": "#06b6d4"
  },
  "next_category_index": 1,
  "candidates": [
    { "title": "...", "url": "...", "summary": "...", "source": "...", "published": "...", "category_id": "...", "category_label": "..." }
  ]
}
```

**`candidates` 배열이 비어있으면** → "후보 없음. 이번 턴 스킵." 출력하고 **여기서 종료**하세요. 아무 파일도 만들지 마세요.

---

## Step 2: 원문 선택

`candidates` 배열의 **첫 번째 항목**을 사용하세요. (이미 최신순 정렬됨)

선택한 항목에서 다음 값을 기억해두세요:
- `title` (원문 제목)
- `url` (원문 URL)
- `summary` (원문 요약)
- `source` (원문 출처명)

---

## Step 3: 스타일 가이드 학습

아래 두 파일을 **반드시 모두 읽으세요**. 이 스타일을 엄격히 따라야 합니다.

1. `prompts/style_guide.md` — Jerry의 문체 규칙 (반말, 이모지, 구조 등)
2. `prompts/author_context.md` — Jerry의 작성자 페르소나

---

## Step 4: 한국어 블로그 글 작성

선택한 원문을 출발점 삼아, Jerry의 톤으로 **한국어** 심층 블로그 글을 작성하세요.

### 길이
- 최소 1500자 ~ 최대 4000자 (공백 제외)

### 구조 (style_guide.md 참고)
1. 도입부: 블록 인용구(`>`)로 카테고리/부제목
2. `## **1️⃣ ...**` / `## **2️⃣ ...**` 번호 매긴 섹션
3. 코드 예시 (새로 작성, 원문 복사 금지)
4. `> 💡 **핵심 질문?**` 형식의 인용구
5. 결론 섹션
6. `## **⭐️ 마지막으로, [관점]에서 이 작업을 통해 배운 점**` — 디자이너/사용자 경험 관점의 메타 인사이트
7. 본문 맨 끝에 **반드시** 출처 각주:
   ```
   ---

   > 참고 원문: [원문 제목](원문 URL)
   ```

### 메타 정보 결정

작성을 시작하기 전에 아래 값들을 먼저 정하세요:

- **title**: 한글 제목 (70자 이내). Jerry 스타일로 `|` 구분자 사용 가능
  - 예: `Next.js App Router 완벽 가이드 | 서버 컴포넌트의 진짜 이점`
- **description**: 한 줄 요약 (80자 이내)
- **slug**: 영문 소문자 + 하이픈. 한글 금지. 60자 이내
  - 예: `nextjs-app-router-server-components`
- **categories**: `candidates.json`의 `category.display_name`을 배열로 사용
  - 예: `["Frontend"]` 또는 `["AI"]`
- **tags**: 영문 소문자 3~7개
  - 예: `[nextjs, react, typescript, server-components]`

---

## Step 5: 썸네일 생성

다음 명령을 Bash로 실행하세요. 경로는 실제 값으로 치환:

```bash
# 오늘 날짜 (한국시간)
DATE=$(TZ=Asia/Seoul date +%Y%m%d)

python scripts/make_thumbnail.py \
  "<한글 title>" \
  "<candidates.json의 category.korean_label 값>" \
  "<candidates.json의 category.color_start 값>" \
  "<candidates.json의 category.color_end 값>" \
  "assets/img/thumbnail/auto-${DATE}-<slug>.png"
```

**주의**:
- 인자에 쌍따옴표 꼭 포함
- slug는 Step 4에서 정한 영문 slug 사용
- 한글 제목에 쌍따옴표 문자(`"`)가 있으면 홑따옴표(`'`)로 치환

---

## Step 6: 포스트 MD 파일 저장

경로: `_posts/YYYY-MM-DD-<slug>.md`
(날짜는 한국 시간 기준. `TZ=Asia/Seoul date +%Y-%m-%d`로 얻음)

파일 내용 형식 (Chirpy 테마 프론트매터):

```markdown
---
title: "<한글 title>"
description: "<한 줄 요약>"
date: YYYY-MM-DD HH:MM:SS +0900
categories: [<카테고리>]
tags: [<tag1>, <tag2>, <tag3>]
image:
  path: /assets/img/thumbnail/auto-YYYYMMDD-<slug>.png
  alt: "<한글 title>"
---

<여기에 본문 마크다운>

---

> 참고 원문: [<원문 제목>](<원문 URL>)
```

**주의**:
- 프론트매터의 `title`, `description`, `alt`에 쌍따옴표 값 안에 쌍따옴표(`"`) 들어가지 않게 주의. 들어가야 할 때는 홑따옴표(`'`)로 치환
- `date`는 한국시간 기준. 예: `2026-04-22 09:00:00 +0900`
- 파일명의 날짜 형식은 `YYYY-MM-DD`, 썸네일 경로의 날짜는 `YYYYMMDD` (하이픈 없음)로 **다름** 주의

---

## Step 7: 상태 업데이트

포스트가 저장되었으면 state.json을 업데이트:

```bash
python scripts/update_state.py \
  <candidates.json의 next_category_index 값> \
  "<원문 URL>" \
  "<한글 포스트 title>" \
  "<candidates.json의 category.id 값>"
```
