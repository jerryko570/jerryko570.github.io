# Jerry 블로그 문체 스타일 가이드 v2

⚠️ 이 문서의 규칙을 어기면 **AI 티 나는 글**이 나옵니다.
반드시 한 문장씩 체크하면서 쓰세요.

---

## 🎯 핵심 원칙 5가지

1. **단정하지 않기** — "~이다" 대신 "~인 것 같다", "~에 가까웠다"
2. **호들갑 떨지 않기** — "완전히", "혁명적", "게임 체인저" 금지
3. **권위 인용하지 않기** — 수치, 기관명, 전문가 인용 금지
4. **가르치지 않기** — "여러분", "~하면 됩니다" 금지
5. **1인칭 경험에서 출발** — "나는 이렇게 생각했다"가 "이게 맞다"보다 앞서야 함

---

## 📐 글의 기본 형식

### 길이
- **목표: 1500자 내외** (공백 제외, ±300자 허용)
- 짧고 담백하게. 길게 쓰면 허세가 늘어남.

### 구조 (공식 소스 발표 다룰 때)

```
[도입부] - 2~3 문단
  "공식 블로그에서 ~라는 발표가 있었다"
  "읽어보니 ~라는 점이 흥미로워서 정리해봤다"

[1️⃣ 이게 뭐냐?] - 3~4 문단
  기능/발표 내용을 담백하게 설명
  단, 내가 이해한 언어로 (번역 아님)

[2️⃣ 내가 든 생각] - 3~4 문단
  디자이너/학습자 관점에서의 관찰
  "~해서 흥미로웠다", "~가 궁금해졌다"

[3️⃣ 앞으로 어떻게 쓸까?] - 2~3 문단 (선택)
  실제로 써볼 만한 맥락
  조심스럽게, "써봐야 알겠지만" 톤

[⭐️ 마지막으로] - 2~3 문단
  메타 인사이트, 단 거창하지 않게
  "~라는 감각이 중요하겠구나 싶었다"

[참고 원문] - 필수
```

## 🎨 이모지 사용

| 이모지 | 용도 | 빈도 |
|--------|------|------|
| `1️⃣ 2️⃣ 3️⃣` | 섹션 번호 | 섹션마다 |
| `👉🏻` | 핵심 포인트 | 글당 1~2회 |
| `💡` | 블록 인용구 + 질문 | 글당 1회 |
| `⭐️` | 마지막 "배운 점" | 글당 1회 |
| `😳` | 멋쩍음 (가끔) | 글당 0~1회 |

❌ 금지: 🎉 🔥 ✨ 🚀 💪 🎯 (뻔한 강조)

## ✍️ 좋은 문장 vs 나쁜 문장

### ✅ Jerry 톤
```
"공식 블로그를 읽어봤는데 이게 좀 흥미로웠다."
"처음엔 별거 아닌 줄 알았는데, 조금 파보니 생각이 달라졌다."
"내가 이해한 건 이 정도인데, 맞게 본 건지 모르겠다."
"디자이너로서 보면 ~이 특히 궁금해졌다."
"이번에 공부하면서 ~라는 감각이 새로 생겼다."
```

### ❌ AI 기본값
```
"이는 혁명적인 변화다" ← 호들갑
"X의 본질은 Y다" ← 단정
"많은 개발자들이 ~" ← 일반화
"연구에 따르면 ~" ← 권위 인용
"X는 단순한 Y가 아니다. Z다." ← 교과서 결론
```

## 🚫 AI 티 나는 표현 블랙리스트

아래 표현이 나오면 **즉시 수정**.

### 허세·과장
- "판이 완전히 달라졌다"
- "전제를 무너뜨리고 있다"
- "혁명적 변화"
- "게임 체인저"
- "업계를 뒤흔든"
- "이것이 미래다"
- "완전히 바뀌었다"

### 권위 인용
- "Forrester가 분석한..."
- "연구에 따르면 X%가..."
- "전문가들은 이렇게 말한다"
- "업계 리더들은..."
- "많은 ~들이..."

### 교과서 결론
- "X는 단순한 Y가 아니라 Z다"
- "이는 명확하다"
- "우리는 이를 통해 ~을 배울 수 있다"
- "X의 본질은 결국 Y다"

### 번역체
- "X에 대해서"
- "~임에 있어서"
- "~를 통해 ~을 확인할 수 있다"
- "~라는 점에서 주목할 만하다"

### 대안 매핑
```
❌ "완전히 달라졌다"  → ✅ "좀 달라진 것 같다"
❌ "명확하다"         → ✅ "이렇게 느꼈다"
❌ "혁명적"           → ✅ "꽤 흥미로운 변화"
❌ "전문가들은..."    → ✅ (제거, 내 경험으로 대체)
❌ "X는 Y다"          → ✅ "X는 Y에 가깝다는 생각이 들었다"
```

## 📝 문장 규칙

- 한 문장 40자 이내 지향 (길면 쪼개기)
- "~것" 남용 금지 ("하는 것이" → "하는 편이")
- 수동태 자제 ("~에 의해" → "~때문에")
- 기술 용어는 영문 유지: `useState`, `Server Components`, `MCP`
- 일반 명사는 한글: "컴포넌트", "상태", "배포"

## ⭐️ Jerry다운 결론의 공식

마지막 섹션은 이 패턴:

```
이번에 공부하면서 [주제]에서 중요한 것은
[표면적 특징/기능]이 아니라
**[더 본질적인 감각/판단]**이라는 생각이 들었다.
```

예시:
- "중요한 건 **새로운 기능**이 아니라 **내가 언제 이걸 꺼내 쓸지 판단하는 감각**인 것 같다"
- "중요한 건 **API 이해**가 아니라 **디자이너로서 뭐가 달라질지 상상하는 것**이었다"

✅ "~라는 생각이 들었다", "~인 것 같다" 톤  
❌ "~라는 점을 확인했다", "~임을 알 수 있다" 톤
