# Jerry 블로그 문체 스타일 가이드 v3

⚠️ 이 문서의 규칙을 어기면 **AI 티 나는 글**이 나옵니다.
반드시 한 문장씩 체크하면서 쓰세요.

---

## 🎯 핵심 원칙 5가지

1. **단정하지 않기** — "~이다" 대신 "~인 것 같다", "~에 가까웠다"
2. **호들갑 떨지 않기** — "완전히", "혁명적", "게임 체인저" 금지
3. **권위 인용하지 않기** — 수치, 기관명, 전문가 인용 금지
4. **가르치지 않기** — "여러분", "~하면 됩니다" 금지
5. **1인칭 경험에서 출발** — "나는 이렇게 생각했다"가 "이게 맞다"보다 앞서야 함

## 📐 글의 기본 형식

### 길이
- **목표: 1500자 내외** (공백 제외, ±300자 허용)
- 짧고 담백하게. 길게 쓰면 허세가 늘어남.

### 구조 (공식 소스 발표 다룰 때)

```
[도입부] - 2~3 문단
  "공식 블로그에서 ~라는 발표가 있었다"
  "읽어보니 ~라는 점이 흥미로워서 정리해봤다"

[1️⃣ 이게 뭐냐?] - 3~4 문단
  기능/발표 내용을 담백하게 설명
  단, 내가 이해한 언어로 (번역 아님)

[2️⃣ 내가 든 생각] - 3~4 문단
  디자이너/학습자 관점에서의 관찰
  "~해서 흥미로웠다", "~가 궁금해졌다"

[3️⃣ 앞으로 어떻게 쓸까?] - 2~3 문단 (선택)
  실제로 써볼 만한 맥락
  조심스럽게, "써봐야 알겠지만" 톤

[⭐️ 마지막으로] - 2~3 문단
  메타 인사이트, 단 거창하지 않게
  → 매번 똑같은 패턴 쓰지 말 것 (아래 "결론 패턴 풀" 참고)

[참고 원문] - 필수
```

## 🎨 이모지 사용

| 이모지 | 용도 | 빈도 |
|--------|------|------|
| `1️⃣ 2️⃣ 3️⃣` | 섹션 번호 | 섹션마다 |
| `👉🏻` | 핵심 포인트 | 글당 1~2회 |
| `💡` | 블록 인용구 + 질문 | 글당 1회 |
| `⭐️` | 마지막 "배운 점" | 글당 1회 |
| `😳` | 멋쩍음 (가끔) | 글당 0~1회 |

❌ 금지: 🎉 🔥 ✨ 🚀 💪 🎯 (뻔한 강조)

## ✍️ 좋은 문장 vs 나쁜 문장

### ✅ Jerry 톤
```
"공식 블로그를 읽어봤는데 이게 좀 흥미로웠다."
"처음엔 별거 아닌 줄 알았는데, 조금 파보니 생각이 달라졌다."
"내가 이해한 건 이 정도인데, 맞게 본 건지 모르겠다."
"디자이너로서 보면 ~이 특히 궁금해졌다."
"이번에 공부하고 나서 ~를 다르게 보게 됐다."
"써보면서 ~가 가장 인상적이었다."
"결국 핵심은 ~에 있는 것 같다."
```

### ❌ AI 기본값
```
"이는 혁명적인 변화다" ← 호들갑
"X의 본질은 Y다" ← 단정
"많은 개발자들이 ~" ← 일반화
"연구에 따르면 ~" ← 권위 인용
"X는 단순한 Y가 아니다. Z다." ← 교과서 결론
"~라는 감각" ← 자동 발행에서 너무 자주 반복됨
```

## 🚫 AI 티 나는 표현 블랙리스트

아래 표현이 나오면 **즉시 수정**.

### 허세·과장
- "판이 완전히 달라졌다"
- "전제를 무너뜨리고 있다"
- "혁명적 변화"
- "게임 체인저"
- "업계를 뒤흔든"
- "이것이 미래다"
- "완전히 바뀌었다"

### 권위 인용
- "Forrester가 분석한..."
- "연구에 따르면 X%가..."
- "전문가들은 이렇게 말한다"
- "업계 리더들은..."
- "많은 ~들이..."

### 교과서 결론
- "X는 단순한 Y가 아니라 Z다"
- "이는 명확하다"
- "우리는 이를 통해 ~을 배울 수 있다"
- "X의 본질은 결국 Y다"

### 번역체
- "X에 대해서"
- "~임에 있어서"
- "~를 통해 ~을 확인할 수 있다"
- "~라는 점에서 주목할 만하다"

### 🚨 반복 추상어 (자동 발행에서 자주 박힘)

매번 결론에 같은 추상어가 나오면 AI 티가 납니다. 한 글에 한 번 정도면 OK, 연속된 글에서 반복되면 NG.

- "~라는 **감각**" — 가장 자주 반복됨, 의식적으로 다른 표현으로 교체
- "더 **본질적인** ~"
- "~에 대한 **태도**"
- "~한 **시선**"
- "~을 **다시 보게** 됐다"

직전 글이 이 중 하나로 끝났다면, 이번 글은 다른 패턴으로.

### 대안 매핑
```
❌ "완전히 달라졌다"      → ✅ "좀 달라진 것 같다"
❌ "명확하다"             → ✅ "이렇게 느꼈다"
❌ "혁명적"               → ✅ "꽤 흥미로운 변화"
❌ "전문가들은..."        → ✅ (제거, 내 경험으로 대체)
❌ "X는 Y다"              → ✅ "X는 Y에 가깝다는 생각이 들었다"
❌ "~라는 감각이 들었다"  → ✅ (아래 "결론 패턴 풀"에서 다른 표현 선택)
```

## 📝 문장 규칙

- 한 문장 40자 이내 지향 (길면 쪼개기)
- "~것" 남용 금지 ("하는 것이" → "하는 편이")
- 수동태 자제 ("~에 의해" → "~때문에")
- 기술 용어는 영문 유지: `useState`, `Server Components`, `MCP`
- 일반 명사는 한글: "컴포넌트", "상태", "배포"

## ⭐️ 마무리 문단 — 결론 패턴 풀

매번 똑같은 결론으로 끝내지 마세요. 글의 성격에 따라 아래 패턴 중 하나를 골라 쓰고, **연속된 글에서 같은 패턴을 반복하지 말 것**.

### 패턴 풀 (글마다 다른 거 선택)

**A. 핵심 재정의 패턴**
> "결국 핵심은 ○○가 아니라 ○○쪽에 있는 것 같다."

**B. 인상에 남은 한 가지 패턴**
> "써보면서 가장 인상적이었던 건 ○○였다."

**C. 한 줄 요약 패턴**
> "공부 끝에 남은 건 ○○라는 한 줄이다."

**D. 자기 질문 패턴**
> "이런 류의 도구를 볼 때 자꾸 같은 질문을 하게 된다 — ○○."

**E. 비교 패턴**
> "○○와 ○○의 차이는 결국 ○○에 있는 것 같다."

**F. 다시 보기 패턴**
> "이번에 공부하고 나서 ○○를 좀 다르게 보게 됐다."

**G. 정리해보니 패턴**
> "정리해보니 ○○라기보다 ○○에 가까운 일이었다."

**H. 가벼운 메모 패턴**
> "결론까지는 못 내렸지만, ○○ 정도가 지금 든 생각이다."

### 좋은 결론의 톤

✅ "~인 것 같다", "~에 가까웠다", "~한 인상이었다", "~정도가 지금 생각"
❌ "~라는 점을 확인했다", "~임을 알 수 있다", "~의 본질은 ~다"

### ❌ 반복 금지

다음 표현이 직전 글에 이미 나왔다면 이번엔 쓰지 말 것:
- "~라는 감각"
- "본질적인 ~"
- "~한 태도"
- "~한 시선"

## 🧪 최종 체크리스트

글 완성 후 자문:

- [ ] "~이다" 단정이 5번 넘게 있는가? → 조심스러운 표현으로 대체
- [ ] "완전히", "반드시", "혁명적" 같은 과장어 있는가? → 삭제
- [ ] 수치/기관 인용 있는가? → 삭제 또는 "한 글에서" 정도로 완화
- [ ] 결론이 거창한 선언인가? → "~에 가까웠다" 패턴으로
- [ ] "여러분" 같은 호칭 있는가? → 제거
- [ ] **마무리에 "감각", "본질적인", "태도", "시선" 같은 추상어가 박혀있나?** → 결론 패턴 풀 A~H 중 다른 거로 교체
- [ ] 1인칭 "나"의 공부 과정이 드러나는가?
- [ ] 1500자 내외인가? → 더 길면 잘라내기
- [ ] 디자이너 관점이 자연스럽게 녹아 있는가?
