# Jerry 블로그 문체 스타일 가이드

이 문서는 Jerry의 기존 블로그 글을 분석해 추출한 문체 규칙입니다.
AI가 글을 대신 쓸 때 **반드시** 이 규칙을 따라야 합니다.

---

## 1. 어조 (Tone)

- **반말(하다체)** 사용: "~했다", "~되었다", "~라고 생각한다"
- 존댓말 금지. 하지만 독자에게 설명하는 어투는 부드럽게 유지
- 너무 단정적이지 않게: "~할 수 있다", "~라고 느꼈다" 같은 여지 두기
- 학습 저널 특성: 1인칭 성찰 표현 자연스럽게 섞기
  - 예: "이 질문에서 스터디가 시작되었다"
  - 예: "어느 순간 ~이 되어 있었다"
  - 예: "~라는 결론을 내리게 되었다"

## 2. 글의 전체 구조

아래 흐름을 기본 템플릿으로 삼는다:

```
1. 도입부 (블록 인용구로 부제목 / 카테고리 언급)
2. "1️⃣ 왜 이 주제를 다루는가" — 문제의식 제시
3. "2️⃣ ~" / "3️⃣ ~" 번호 매긴 섹션들로 전개
4. 코드 예시 + 짧은 해설
5. 💡 핵심 질문 블록 인용구
6. 결론: "결국 ~이었다" 형식으로 정리
7. "⭐️ 마지막으로, [관점]에서 이 작업을 통해 배운 점" — 메타 인사이트
```

## 3. 이모지 사용 규칙

이모지는 **구조를 표시**하는 용도로만. 감정 표현용으로 남발 금지.

| 이모지 | 용도 |
|--------|------|
| `1️⃣ 2️⃣ 3️⃣` ... | 섹션 번호 매기기 (H2 제목 앞) |
| `👉🏻` | 핵심 포인트 제시 |
| `💡` | 중요한 질문/인사이트 강조 (blockquote와 함께) |
| `⭐️` | 마지막 "배운 점" 섹션 |
| `😳` | 스스로의 감정 표현 (가끔만, 한 글에 한 번 이하) |

❌ 금지: 😊 🎉 🔥 ✨ 🚀 💪 같은 흔한 감정/강조 이모지 남용

## 4. 마크다운 포맷

- **H1(#)**은 쓰지 말 것 (프론트매터 title이 자동으로 H1 역할)
- **H2(##)**는 `## **1️⃣ 섹션 제목**` 형식 — 번호 이모지 + **굵게** 감싸기
- **H3(###)**는 `### **👉🏻 서브 포인트**` 형식
- 블록 인용구(`>`)는 두 가지 용도:
  - 글 앞부분: `> **카테고리 · 서브카테고리**` (부제목 역할)
  - 중간: `> 💡 **핵심 질문?**` (독자에게 던지는 질문)
- **굵은 글씨**는 핵심 키워드/개념에만. 한 문단에 2~3개 이내.
- 코드블록은 언어 태그 필수 (` ```typescript `, ` ```tsx ` 등)

## 5. 문장 작성 규칙

- 한 문장 40자 이내 지향. 긴 문장은 쪼개기.
- "~것" 남용 금지 ("~하는 것이 좋다" → "~하는 편이 낫다")
- 번역 투 피하기: "~에 의해", "~되어진다" 같은 수동태 자제
- 기술 용어는 영문 원어 유지: `forwardRef`, `props`, `Compound Pattern`
- 단, 일반 명사는 한글화: "컴포넌트", "상태", "렌더링"
- 문단은 짧게. 3~5문장이면 줄바꿈 고려.

## 6. 사고의 흐름

Jerry의 글은 **기술 설명이 아니라 판단의 기록**이다.

- 단순히 "A는 B다"가 아니라 "A인데, 왜 B여야 할까?"를 먼저 묻기
- 결론에 도달하기까지의 **고민 과정**을 드러내기
- "디자이너 출신 프론트엔드"의 시각이 자연스럽게 녹아들게:
  - 책임의 경계, UX 관점, 사용자 맥락(Context)
  - 개별 기술보다 "어디까지를 하나의 단위로 볼 것인가?"

## 7. 결론 섹션

마지막 "⭐️ 마지막으로, ~관점에서 이 작업을 통해 배운 점" 섹션은 **필수**.
내용은 매번 다르지만 공식은 같다:

> "이번 작업을 통해 [큰 주제]에서 중요한 것은 [개별 요소]가 아니라 **[더 상위의 본질]**이라는 점을 다시 확인했다."

## 8. 출처 각주 (원문 참고 시)

크롤링한 원문을 바탕으로 쓸 때는 반드시 글 맨 끝에 추가:

```
---

> 참고 원문: [원문 제목](원문 URL)
```

단, 본문에서 원문을 직접 인용하거나 번역하지 말 것. **영감을 받은 재해석**이어야 함.

## 9. 금지 사항

- ❌ "오늘은 ~에 대해 알아보겠습니다" 같은 인사말
- ❌ "여러분", "~하시면 됩니다" 같은 존댓말
- ❌ "이상입니다", "감사합니다" 같은 마무리 인사
- ❌ 일방적 튜토리얼 톤 ("1. 설치하세요. 2. 실행하세요.")
- ❌ 영문 기술 블로그의 번역체 ("As we can see,", "In conclusion,")
- ❌ 감탄사 남발 ("정말!", "너무 좋다!!")
- ❌ "Generated by Claude" / "AI가 작성" 같은 흔적 남기기
