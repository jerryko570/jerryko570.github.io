[위클리페이퍼] (9) TypeScript를 사용하는 이유

1. 타입스크립트를 사용하는 이유

  • 자바스크립트 (동적 타입 언어) 는 자유롭지만, 오류를 실행 후 (Runtime 이후) 에 발견해 위험하고,
    타입스크립트 (정적 타입 언어) 는 엄격하지만, 실행 전 (Compile 단계) 에 컴파일러가 타입 오류를 미리 잡아준다.

2. 타입스크립트 동작 원리를 엔진으로 이해하기

2-1. 브라우저는 타입스크립트를 이해하지 못함

  • 브라우저는 자바스크립트 V8 엔진만 이해할 수 있고,
    .ts 파일을 바로 읽을 수 없기 때문에 TypeScript ➡ JavaScript로 변환(Compile) 해야 실행할 수 있다.

    💡 브라우저는 타입스크립트 엔진이 아니라 자바스크립트 엔진을 사용한다.

3. 타입스크립트의 실행 흐름

3-1. 작성 단계 (Developer)

  • 개발자가 .ts 파일로 코드를 작성한다.
  • 타입, 인터페이스, 유틸리티 등은 개발 중에만 존재하고,
    실행 시에는 모두 제거된다.

3-2. 컴파일 단계 (TypeScript Compiler, tsc)

  • 타입스크립트 컴파일러가 코드를 검사하고,
    모든 타입 관련 코드를 제거한 뒤 순수 자바스크립트 코드로 변환한다.

3-3. 실행 단계 (JavaScript Engine)

  • 변환된 .js 파일을 브라우저나 Node.js의 엔진(V8 등) 이 실제로 실행한다.

4. 타입스크립트가 개발 효율을 높이는 이유

  • 자동완성과 에러 힌트 덕분에 개발 속도가 빨라진다.
  • 함수나 컴포넌트의 데이터 구조가 명확해져 협업이 쉬워진다.
  • 타입 정보 덕분에 버그 발생 가능성이 줄어든다.

💡 학습정리

타입스크립트는 브라우저에서 바로 실행되지 않는다. 컴파일러가 타입을 검사하고 자바스크립트로 번역한 뒤 엔진이 실행한다.
